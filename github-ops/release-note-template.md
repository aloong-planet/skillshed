# Release Note 模板(面向普通用户的桌面 app)

> 填写规则(先读):
> - **面向最终用户写**,写"用户能感知的变化",不要贴 `feat:`/`fix:` 的 commit 原文。把技术改动翻译成人话(例:"图标 SVG 化" → "图标大小统一、更清晰")。
> - **不使用任何 emoji / 图标**,正文纯文字。
> - **分层**:开头"版本说明"用 1–3 句白话概括本版最值得关心的变化,再往下分组列细节。
> - **按需删小节**:没有的组(破坏性变更/已知问题等)整节删掉,不留空标题。
> - **GitHub Release 的 Title 只写「版本号-类型」,不带任何亮点说明**:正式版(干净 tag)= `<tag>-release`(如 `v1.2.0-release`),预发布(`-beta`/`-rc`/`-alpha`/`-dev` 后缀 tag)= 直接用带后缀的 tag 名(如 `v1.2.0-beta`)。所有详细信息(亮点/变更/下载)全部放正文,标题不重复。
> - **macOS 公证/非公证二选一**:见"下载与安装"里的判断规则,按本次 tag 形态删掉不适用的那段。
> - 提交/note/tag 一律**无 AI 署名、无 co-author**(见 SKILL.md 第 1 节)。

首次使用提示
- macOS:已通过 Apple 公证。首次打开时系统会弹一次"是从互联网下载的 App,确定要打开吗"(下方会注明"Apple 已检查,未发现恶意软件"),点"打开"即可,以后不再提示——这是所有从浏览器下载的 App 都有的一步,不是安全警告。**Apple 芯片(M 系列)选 arm64、Intel 选 x64、不确定选 universal**(左上角  → 关于本机 可看芯片型号)。首次使用需要系统权限的功能(如截图)时,系统会请求相应权限(如"屏幕录制"),请在"系统设置 → 隐私与安全性"中允许 <项目>,然后重启 App 生效。
- Windows:安装包未做数字签名,若弹出 SmartScreen 蓝色提示,请点"更多信息 → 仍要运行"。首次启动时请在防火墙弹窗中允许访问"专用网络",否则局域网内可能搜索不到设备。

首次使用提示
- macOS:此为迭代测试版,已签名但未经 Apple 公证。**Apple 芯片(M 系列)选 arm64、Intel 选 x64、不确定选 universal**(左上角  → 关于本机 可看芯片型号)。从网络下载的 App 会被系统标记隔离属性,直接双击可能提示"已损坏 / 无法验证开发者"。把 App 拖到"应用程序"后,在终端执行以下命令去掉隔离标记即可正常打开(只需执行一次):

  ```bash
  xattr -dr com.apple.quarantine "/Applications/<项目>.app"
  ```

  若仍提示无法打开,可再右键点击 App → 选择"打开",或在"系统设置 → 隐私与安全性"中点"仍要打开"。首次使用需要系统权限的功能(如截图)时,请在"系统设置 → 隐私与安全性"中允许 <项目>,然后重启 App 生效。
- Windows:安装包未做数字签名,若弹出 SmartScreen 蓝色提示,请点"更多信息 → 仍要运行"。首次启动时请在防火墙弹窗中允许访问"专用网络",否则局域网内可能搜索不到设备。
