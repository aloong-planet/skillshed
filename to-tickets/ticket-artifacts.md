# Ticket 产物与文档同步清单

使用本文件的文档同步规则时，必须完整读取 [文档同步与记录维护](../implement/document-sync.md)。

## 身份与路径

- 必须在 `docs/.workings/<slug>/` 下，使用同一个 `ticket-<id>-` 前缀命名本票的 `review-code.md`、`review-tests.md` 和 `doc-sync.md`；`<slug>` 必须取本 feature 已使用的施工目录标识，第三份产物的标题必须写为“文档同步清单”。本地票的 `<id>` 必须使用现有编号（例如 `06`）；tracker 票必须使用可作文件名的实际标识，标识需转换时必须在票中记录原标识与前缀的对应关系，并确认在本 feature 内唯一。
- 必须在票中声明上述三份产物路径；跨 feature 引用票时，必须同时记录 feature slug 与票标识。不得只用裸票号指向其它 feature 的票。
- 必须保留 feature 级 `checklist.md` 与 `final-regression.md` 的名称和共享职责；不得以本票文档同步清单替代需求覆盖清单或交叉回归报告。

## 文档同步清单结构与状态

- 必须把文档同步清单写成轻量待办：只列本票需要回写的事项，不得复制产品验收清单、审查明细或完整阶段状态表。
- 必须按“同一同步事项、同一触发时点”组织一行；可独立核销、可能处于不同完成状态的事项必须拆行。同一行可包含多份文档，不得仅因文件不同而拆行。
- 必须使用下表三列；成品清单必须按实际事项展开，不得保留填写指令。清单标题、表头、状态取值与流程验收项名称写进项目时，必须按 [产物固定名称](../repo-scaffold/artifact-names.md) 书写。

| 同步事项及触发时点 | 涉及文档 | 状态与说明 |
|---|---|---|
| 必须简述要同步什么、何时处理，不得仅写“同步文档” | 必须链接涉及的文件或 tracker 对象；仅在目标容易混淆时补章节或条目标识 | 必须按下方状态规则写当前状态及简短说明，引用已有证据，不得复制整份报告或日志 |

- 事项所列触发条件已满足，且涉及文档全部核对或更新完成、依据有效时，必须标为“已完成”，链接支持结论的改动或核对记录；同一行仅完成部分文档时不得标为已完成。
- 事项适用且已确认触发条件尚未满足时，必须标为“待触发”，说明等待的事件；其他尚未完成或未核实的事项必须标为“待处理”，说明剩余文档、工作或阻断。
- 以某个 PR 合并为触发条件的事项，在该 PR 内必须标为“已完成”并注明随本 PR 合并完成，上文“已完成”与“待触发”两条的触发条件判定对它不适用；在其它 PR 或文件中仍按那两条标注。缘由、合并后的回写，以及不经 PR 的合并以被合并的分支代替 PR，见 [文档同步与记录维护](../implement/document-sync.md) 的“合并事件只在被合并的 PR 内记录”。
- 已确认不受影响或不适用的类别不得为凑齐分类而列行；既有事项经核实已不适用时，必须从现行待办中移除，并在本轮已有改动说明中写明原因，不得将移除记成完成。适用性未核实时必须保留待处理。

## 切票时预列

- 发布已确认的 tickets 时，必须按“文档同步清单结构与状态”创建各票清单，文件头链接关联票，并依据本票范围及已确认的交付安排预列已知同步事项，包括尚未触发的适用事项；审查尚未执行时，不得预建带结论的审查记录。
- 必须按 [文档同步与记录维护](../implement/document-sync.md) 确定实际受影响文档并在实施中补充发现。

## 票内最终流程验收

- 必须在每张票的“流程验收”中生成下表三项，均标为 **Evidence** 并指向本票产物；必须将规则依据与实际证据位置区分，未执行时不得把规则链接作为完成证据。仅生成票或施工材料说明时，必须按本表生成验收要求；实际进入交付或处理验收反馈时，必须再调用 `/implement`，按其“交付”与“验收反馈回写”判定阶段，不得以生成要求代替执行门禁。

| 验收项 | 生成要求 |
|---|---|
| 代码审查 | 必须要求本票代码审查完成，结论、发现及处置可复查，并链接代码审查记录 |
| 测试审查 | 必须要求本票测试审查的设计审查与实现后复核均已完成，结论、验证缺口及处置可复查，并链接测试审查记录 |
| 文档同步 | 必须将 [文档同步与记录维护](../implement/document-sync.md) 的“核销前的范围复核”展开为票内可直接核对的验收条件，写明现行状态与实际结果的一致性检查，以及遗漏事项、过期说明的处理，不得只写检查名称或限于已有清单；还须要求按本文件的“文档同步清单结构与状态”核对清单，无待处理项，并链接清单作为核销凭据；待触发项必须说明后续安排，不得记为已完成 |

## 既有材料与无票入口

- 接续旧票且缺少本规范产物时，必须为当前工作补建清单及路径声明，并核对可复用的旧证据适用范围；不得为无关历史票批量补档。复用旧共享审查报告时，必须链接相关证据并写明本轮核对结论，不得复制旧结论冒充本票新审查；现行记录与原始证据的维护必须按 [文档同步与记录维护](../implement/document-sync.md)执行。
- 无 ticket 的 spec 实施或独立审查不得虚构票号；需落盘时，必须使用当前工作的 `docs/.workings/<slug>/review-code.md`、`review-tests.md`，其中独立审查只生成实际执行的类别；不得因此强制拆票或创建 ticket 文档同步清单。
