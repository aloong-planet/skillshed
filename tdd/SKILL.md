# Test-Driven Development

TDD 是测试与实现交替推进的纵切循环,哪些测试必须先红见「循环规则」节。本 skill 是让循环产出**值得留下的测试**的参考:什么是好测试、测试站在哪、反模式、循环规则。每个循环前后都对照,不要事后补看。
探索代码库时读 CONTEXT.md(测试名与接口词汇对齐领域语言),尊重所触及区域的 ADR。

## 什么是好测试

经**公开接口**验证**行为**,不碰实现细节。代码可以整个重写,测试不该动。好测试读起来像规格说明——"user can checkout with valid cart" 直接告诉你存在什么能力——并在重构后存活。
样例与红旗见 [tests.md](./tests.md),mock 纪律见 [mocking.md](./mocking.md)。

## Seam——测试站在哪

**seam** 是测试所站的公开边界:在此观察行为,不把手伸进内部。测试只写在 seam 上,永不对着内部写。

- **预定 seam**:写任何测试前先写下要测的 seams。spec 的 Testing Decisions 已确认过的直接用;**seam 不明或需新建时才问用户,否则自己定**。
- **缺 seam 是设计信号(硬规则)**:被迫 cast 私有成员/直写内部状态才能测 = 模块缺注入 seam——**先补构造注入**(时钟/网络/存储/随机数经构造参数注入)**再测,不许 cast 凑**。想测到接口背后,说明模块形状不对(interface is the test surface)。
- **可达状态规则**:测试构造的一切状态必须经**公开路径可达**。公开接口到不了的状态,测它就是测幻觉——找该状态的真实入径改写,找不到就说明该断言守的是不存在的场景。**判据**:这份 setup 换成"经公开接口一步步做到该状态"能不能做到?做不到,就是手工摆出来的。

## 覆盖来源

覆盖清单 = spec 的**「失败模式与边界」节**(按用户操作序列穷举的产物),逐条转为纵切循环直到清空。
**测不到的**(无行为触发点的接线等)不硬测:在测试文件头注明缺口与补测条件——诚实的缺口好过造假的绿(详见 /review-tests)。
**读外部数据的用例,fixture 至少一例照真实样本的形态造**:覆盖清单来自 spec,fixture 若也来自"我以为数据长什么样",两者同源——spec 的盲点被 fixture 原样继承,测再多只是把同一个想象验证多遍。判据是形态而非数值:真实数据里有而我没想到的**结构特征**(嵌套、引用、混合类型、异常但合法的写法)才是盲点所在。

## 反模式(样例见 tests.md)

- **实现耦合**:mock 内部协作者、测私有方法、断言调用次数/顺序、绕过接口旁路验证。征兆:重构没改行为,测试却碎。
- **同义反复**:期望值按实现同款方式重算,构造性恒真。**期望值三禁**——禁与实现同算法重算;禁复用输入对象作期望;禁断言 import 进来的同一常量。期望值必须来自独立真值:已知字面量、手算例、规格。
- **横切**:先写完所有测试再写实现。批量测试验证的是**想象**的行为,并在理解实现前就锁死测试结构。改用纵切:一测→一实现→重复,每个测试都是回应上个循环所学的 tracer bullet。

## 循环规则

- **哪些测试必须先红**:先红指测试在它覆盖的代码写成或改动之前就跑出失败。修 bug 以外的测试(新功能、行为变更等)按项目能力 `red-green-mutation` 判定(读法按全局指令「项目能力声明」节):启用的,必须完整读取 [先红与变异](./red-green-mutation.md) 并执行其「先红」节;未启用的,不要求先红,按全局指令写明跳过。修 bug 的测试不受该能力管辖,一律必须先对着未修的代码红一次再修。
- **红要红得对**(凡上一条要求先红的测试,这是先红的完成判据,不是额外建议):红是三重验证——①代码确实没有该行为 ②测试确实能失败 ③失败原因确实是预期的那个断言(不是 setup 崩溃/typo/import 错)。**「测试跑出红色」不等于先红已完成**,未过判据的红不算数。**预期红却绿了 = 重要发现**:要么行为已存在(你理解错了现状,别写重复实现),要么测试是坏的(断言过弱/没 await/测错对象)。读失败信息,不要只看见红色就满足。
- **红的来源必须是真实可达的状态**:绕过系统自身的状态管理、手工摆出的场景所产生的红,红的是一个不存在的世界(判据见「可达状态规则」)。**红也需要归因**——先确认这个红是被测行为缺失造成的,再动手让它变绿。
- **测穿构建产物的用例,跑之前先确认产物是本次改动的**:端到端、烟测这类读构建输出的检验,若运行器不触发构建,量到的是上一次的产物——此时"红"与"绿"都与本次改动无关。
- **一次一纵切**:一个 seam、一个测试、一个最小实现;不预写未来的测试,不加投机功能。判据是每条测试都说得出它在回应上一循环学到的什么;说不出,就是在横切——代价见「反模式」节,不在此复述。
- **重构不在循环里**:归 review 阶段(`/review-code`),循环只做够过的实现;重构的安全网就是循环攒下的测试。
