# ADR 格式(MADR minimal 定制版)

ADR 放 `docs/adr/`,顺序编号:`0001-slug.md`。扫目录取最高已有号 +1,编号不复用。
懒创建:第一条 ADR 需要时才建目录,**连同 `README.md`**(见文末)。
模板与本文件中写进 ADR 的固定名称(段名、状态取值、后果标签、「未留档」、索引表头与分组名),必须按 [产物固定名称](../repo-scaffold/artifact-names/domain-modeling.ADR-FORMAT.md) 书写。

## 模板(五段全必填)

```md
# ADR-NNNN: {决策短标题}

- 状态: 提议 | 已接受({采纳日期}) | 已被 ADR-XXXX 取代

## 背景与问题

{2-3 句:什么处境,要解决什么问题。价值中立,陈述各方作用力。}

## 备选项

1. **{选中的方案}**
2. {被否决的方案}——否决理由
3. {暂缓的方案}——暂缓理由与重启条件

## 决策

{选定**方案 N**:决策本身,主动语态,"我们采用……"}

## 后果

- 正面:{...}
- 负面:{...}
- {正面、负面、中性都要写,不许只挑好的}

## 来源

{证据出处:设计文档/复盘/实测记录/外部资料链接}
```

**「备选项」段的重要性**:ADR 防的头号问题是后人(或 agent)重提已被否决的方案——"为什么不是别的"与"选了什么"同等重要;缺少此段,决策只剩结论、丢失排除过程,同一批备选未来会被重新评估一遍。
**诚实条款**:无留档的备选须标注"(未留档)"并说明性质(定位排除/业界常规备选),**不得事后编造对比**——区分"当年真实比较过"与"事后合理化"。

## 三态规则(拍板时机)

- **已接受**(状态行须带采纳日期):证据已闭环的决策——范围/定位类(对话即证据)、调研已坐实的架构方向。落盘后**只追加不改写**;要推翻就新开 ADR 并把旧条标"已被 ADR-XXXX 取代"。
- **提议**:方向已定但证据未闭环(需实测/上线/实现验证的选型)。**此状态允许改写**;验证通过升级"已接受"(补日期),被推翻则改写或删除。
- grilling 中只拍"证据已在桌面上"的决策;实现层技术路径、依赖外部实测的选型,落"提议"态,或先 `/prototype` 拿到证据再拍。实现期冒出的新决策当场补条目。

## 收录边界

只收**本项目**的架构决策。流程/工作流/文档格式类约定是跨项目内容,**不入项目 ADR**(归 memory / skills)。

## 何时该写(下列门槛同时满足;任一不满足就跳过)

1. **难逆转**——之后改主意的代价可观
2. **无上下文会费解**——未来读者会问"当年为什么这么搞"
3. **真实 trade-off 的产物**——存在真备选,因具体理由选了其一

符合的典型:
- **架构形状**("monorepo"、"写模型事件溯源,读模型投影进 Postgres")
- **上下文间集成模式**("Ordering 与 Billing 走领域事件,不走同步 HTTP")
- **带锁定的技术选型**(数据库/消息总线/认证/部署目标——换掉要一个季度的那种,不是每个库)
- **边界与范围决策**(明确的"不做"与"做"同等值钱)
- **刻意偏离显然路径**("不用 ORM 手写 SQL,因为 X"——拦住下一个人来"修好"它)
- **代码里看不见的约束**(合规要求、伙伴契约的性能红线)
- **非显然的否决**(考虑过 GraphQL 选了 REST——不记下来,六个月后有人会再提一遍)

## README(索引 + 规范声明)

首次创建 `docs/adr/` 时同时生成 `README.md`:
- 头部一段声明本仓库 ADR 规范:模板段落全必填(含备选项)、状态取值与升级规则、只追加、收录边界、写入门槛;
- 下接 `| # | 决策 | 状态 |` 索引表。

**每落一条 ADR 往索引追加一行**——索引腐烂等于没有索引。
**状态列与条目内状态行同步维护**:提议升级为已接受、条目被取代时,两处一起改。索引即"现行集合"的过滤视图:日常推理只需载入未被取代的条目,全集只在考古时用。
**领域分组(启用阈值:约 30 条或单表扫读吃力,未达阈值维持单表)**:启用时只把索引表拆成分组小节,文件永远平铺顺序编号(分子目录破坏编号与引用稳定性)。分组键取自 CONTEXT.md 的术语聚类,不另发明分类词;一条只进一组(按主要影响面,跨域归"总体");组数 5-9,组内 ≥2 条才成组。
