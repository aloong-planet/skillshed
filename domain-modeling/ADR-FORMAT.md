# ADR 格式(MADR minimal 定制版)

每条 ADR 必须陈述项目此刻生效的决策——规则、约束与取舍,不得记决策的历史;历史在 git 里。

ADR 放 `docs/adr/`,顺序编号:`0001-slug.md`。新条目取用过的最高编号 +1,编号不复用:取最高编号时必须连同 README 索引「已退役编号」节里的编号、以及 git 历史里出现过的条目文件一起比。
懒创建:第一条 ADR 需要时才建目录,**连同 `README.md`**(见文末)。
本文的「同一次改动」指一起交给用户审查的那次改动,经 PR 交付的即同一个 PR。
模板与本文件中写进 ADR 的固定名称(段名、状态取值、后果标签、「未留档」、索引表头、分组名、「已退役编号」与「作废」),必须按 [产物固定名称](../repo-scaffold/artifact-names/domain-modeling.ADR-FORMAT.md) 书写。

## 分流:什么写进 ADR

一项决策同时满足下列三条门槛、且按下表归 ADR 的,才写 ADR;任一门槛不满足的不写 ADR,下表归到别处的写到那里。

1. **难逆转**——之后改主意的代价可观
2. **无上下文会费解**——未来读者会问"当年为什么这么搞"
3. **真实 trade-off 的产物**——存在真备选,因具体理由选了其一

| 要记下的是什么 | 写到哪里 |
|---|---|
| 本项目的架构决策(典型见下),以及产品行为、计算口径背后的取舍 | ADR |
| 本项目在流程问题上的取舍:采用哪种做法、为什么 | ADR;只写本项目的选择与理由,不复述那种做法自身的规则 |
| 跨项目通用的流程规则本身 | 管那项工作的 skill |
| 约束改代码的人的规则 | 项目 `AGENTS.md` 的不变量;它背后的取舍满足三条门槛的,取舍另按第一行写 ADR |
| 产品行为、计算口径本身的陈述 | 该功能的 spec;它背后的取舍写成了 ADR 的,spec 引用那条 ADR |
| 事故 | 复盘 |
| 代码怎样实现一项决策 | 那段代码的注释 |

架构决策的典型:
- **架构形状**("monorepo"、"写模型事件溯源,读模型投影进 Postgres")
- **上下文间集成模式**("Ordering 与 Billing 走领域事件,不走同步 HTTP")
- **带锁定的技术选型**(数据库/消息总线/认证/部署目标——换掉要一个季度的那种,不是每个库)
- **边界与范围决策**(明确的"不做"与"做"同等值钱)
- **刻意偏离显然路径**("不用 ORM 手写 SQL,因为 X"——拦住下一个人来"修好"它)
- **代码里看不见的约束**(合规要求、伙伴契约的性能红线)
- **非显然的否决**(考虑过 GraphQL 选了 REST——不记下来,六个月后有人会再提一遍)

## 模板(五段全必填)

```md
# ADR-NNNN: {决策短标题}

- 状态: 提议 | 已接受({现行决策经用户确认的日期})

## 背景与问题

{只写要解决的问题,与作用在它上面的各方约束;价值中立,至多 3 句。}

## 备选项

1. **{选中的方案}**
2. {被否决的方案}——否决理由
3. {暂缓的方案}——暂缓理由与重启条件

{每个选项占一项,至多 2 句。}

## 决策

{只写现行规则本身:选定**方案 N**,主动语态,"我们采用……"}

## 后果

- 正面:{...}
- 负面:{...}
- {只写此刻仍成立的后果;正面、负面、中性都要写,不许只挑好的;每条占一项,至多 2 句。}

## 来源

{只写证据出处的指针,以及决策所依据的关键数字,各带其适用前提。}
```

**「备选项」段的重要性**:ADR 防的头号问题是后人(或 agent)重提已被否决的方案——"为什么不是别的"与"选了什么"同等重要;缺少此段,决策只剩结论、丢失排除过程,同一批备选未来会被重新评估一遍。
**诚实条款**:无留档的备选须标注"(未留档)"并说明性质(定位排除/业界常规备选),**不得事后编造对比**——区分"当年真实比较过"与"事后合理化"。

## 各段的内容

各段只得写模板里该段占位符说明的内容;任何一段都不得写下列内容(下称禁写清单):

- 规则的来历:它怎样被提出、怎样被发现需要
- 验证或落地的经过,证据闭环的记录
- 已付清的一次性代价:迁移了多少处、改了哪些测试
- 代码怎样实现这项决策;界面细节
- 测量的取得过程(数字本身按模板「来源」段保留)
- 行号;逐个位置列出的清单(哪些文件、哪几处)
- 别的 ADR、spec 或 skill 已写的内容的复述(只写指向)
- 关于"这项决策怎样记进文档"的选项

## 篇幅

- 各段的句数上限见模板该段的占位符。
- 全文除标题与状态行外按 Unicode 字符计:项目 `capabilities.toml` 的 `working-language` 为 `zh` 的,至多 1,800 字符;为其他语言的,至多 5,000 字符。两个上限按中英同等信息量换算:中英对照的界面文案里,英文字符数约为中文的 2.8 倍。
- 超出上限的,先把禁写清单里的内容按「删掉的内容去哪」节移走;仍超出的,按决策拆成几条,每条各自满足本节。

## 状态与修改

- **提议**:方向已定但证据未闭环(需实测、上线或实现验证的选型)。验证通过即升级为「已接受」,状态行写上用户确认它的日期;被推翻的,按「编号退役」节作废。
- **已接受**:证据已闭环的决策——范围、定位类(对话即证据),调研已坐实的架构方向。状态行的日期是现行决策经用户确认的日期。
- **就地修改**:条目只写现行决策;决策变了就改这一条,不得新开条目去取代它。
  - 改变条目选了什么、否决了什么、接受了什么后果的,写入前必须经用户确认;放弃的旧做法写成该条的一个被否决选项,附放弃的理由;状态行的日期改为这次确认的日期。改写中删掉一个被否决选项,或一条此刻仍成立的负面后果的,同样是改变决策;删去的属禁写清单的不算。
  - 不改决策的改写(压缩、合并条目、修正过时的事实)不必事先确认,状态行的日期不动;每一条这样的改写都必须列进这次改动交给用户审查的记录(经 PR 交付的即 PR 描述),没有这样的记录的,把改写清单报告用户。
- **新决策落哪条**:新决策使某条已有 ADR「决策」段的某句不再成立、或需要在那里补一句的,改那一条,这样的条目有几条改几条;一条都没有的才新开。改后超出上限的,按「篇幅」节最后一条办。
- 实现期冒出的新决策,当场按上一条写进 ADR。

## 编号退役

条目并入另一条,或其决策整个作废的,它的编号退役,必须在同一次改动里做完下列三步:

1. 删除它的文件。
2. 全仓检索这个编号(代码注释里的也算),把每一处引用改指它并入的条目;作废的,删去这处引用。
3. 在 README 索引的「已退役编号」节记一行:这个编号,以及它并入的条目编号或「作废」。

## 删掉的内容去哪

禁写清单里的内容离开条目之前,必须先在它的现行归宿里找到,找不到的先补进归宿再删:界面行为归 spec,代码怎样实现归那段代码的注释,约束归项目 `AGENTS.md` 的不变量。没有现行归宿的(如规则的来历、验证与落地的经过、已付清的代价、测量的取得过程)直接删去,git 里留着。

## 旧规则下写的条目

- 一次改动改了某条 ADR 自身的陈述——它的决策、备选项、后果,或它陈述的事实——而这条 ADR 有不合本文之处的,必须在同一次改动里把整条按本文重写:
  1. 状态行或注记标明与它互为取代、扩展或修订的条目并入它,并入的条目按「编号退役」节退役;
  2. 禁写清单里的内容按「删掉的内容去哪」节移走;
  3. 篇幅压进「篇幅」节的上限。

  只把一处引用改指另一个编号,不算改了它自身的陈述。没有被改到的条目保持原样。
- 本文的规则在每个项目里立即适用。项目 `docs/adr/README.md` 头部的规范声明仍写着旧规则(只追加不改写、「已被取代」状态)的,必须在该项目第一次写或改 ADR 的那次改动里,按「README」节一并改写。

## 自查

写或改一条 ADR 之后、提交之前,必须逐段对照模板里该段占位符的说明与禁写清单,并按「篇幅」节数句数与字符数;还必须核对项目 `docs/adr/README.md`:头部的规范声明写的是本文的规则,索引表与现有条目一一对应,「已退役编号」节列全已退役的编号。有一处不合的,改到合为止。

## README(索引 + 规范声明)

首次创建 `docs/adr/` 时同时生成 `README.md`:
- 头部声明本仓库 ADR 规范:分流表与三条门槛、五段全必填及各段只写什么、禁写清单、篇幅上限、状态取值、经用户确认后就地修改、编号退役;
- 下接 `| # | 决策 | 状态 |` 索引表;有退役编号的,表后接「已退役编号」节,一行一个编号及其去向。

**索引与条目同步维护**:新增条目加一行;条目的标题或状态变了,同一次改动里改它那一行;编号退役时,同一次改动里把它移出索引表、记进「已退役编号」节——索引腐烂等于没有索引。
**领域分组(启用阈值:约 30 条或单表扫读吃力,未达阈值维持单表)**:启用时只把索引表拆成分组小节,文件永远平铺顺序编号(分子目录破坏编号与引用稳定性)。分组键取自 CONTEXT.md 的术语聚类,不另发明分类词;一条只进一组(按主要影响面,跨域归"总体");组数 5-9,组内 ≥2 条才成组。
