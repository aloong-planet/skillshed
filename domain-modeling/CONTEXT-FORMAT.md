# CONTEXT.md 格式

模板的节名写进项目时,必须按 [产物固定名称](../repo-scaffold/artifact-names/domain-modeling.CONTEXT-FORMAT.md) 书写。

## 结构

```md
# {上下文名}

{一两句:这个上下文是什么、为何存在。}

## Contents(目录) {全文超过 100 行时必有}

{按术语簇列出每个术语的名称;要求见「写法」节。}

## Language(术语)

**{术语,如 订单(Order)}**:
{定义它「是什么」,不是「做什么」;句数与第二句的用途见「写法」节。}
_Avoid_: {同义词,如 购买、交易}

**{术语,如 发票(Invoice)}**:
{定义,如 交付后向客户发出的付款请求。}
_Avoid_: {同义词,如 账单、付款单}

## Relationships(关系) {可选节}

{概念间关系,一行一条(如"发现 = announce + register 组成双向发现")。仅当关系本身承载易混信息时才写。}

## Flagged ambiguities(已消解歧义) {可选节}

{曾经混用、现已裁定的术语;写法见「写法」节。}
```

## 收录判据

一条内容同时满足下列各条才准写入:

1. **本项目特有**:通用编程概念、框架或工具的行为不收,哪怕项目大量使用。
2. **读代码推不出**:读代码就能得到的事实不收,哪怕写下来查起来更方便。
3. **属于词汇**:内容是下列三类之一——术语的含义与该避免的同义词、概念间关系、已消解的歧义。
4. **术语不解释就会用错**(只对术语):至少满足一条——本项目里有一个会和它混用的词或概念,并在定义或 `_Avoid_` 里点了名;或它的含义不能从字面推出(自造词,或在本项目里收窄、改变了通常含义的词)。字面即可推出含义、`_Avoid_` 里只有泛泛近义词的词不收,由用到它的 spec 或 ADR 自己定义。

不满足的内容按「禁止形态」表找归宿;表里找不到归宿的,不写,先问用户放哪里。

## 写法

- **有立场**:同一概念存在多个词时,选定最佳的一个,其余全部进 `_Avoid_`;没有同义词的术语省略 `_Avoid_` 行。
- **术语定义至多两句**:第一句说它是什么;第二句只用于点名混淆对象或纠正一种误读,不写性质、行为或后果。`_Avoid_` 里每个词至多附一个括注,说明为何避免。
- **已消解歧义每条至多两句**,写明旧义作废、现行词与裁定出处;旧词已不出现在本文件以外任何文档里的,删掉该条。
- **每条都要能被证伪**:定义写成对着代码或行为可核的陈述,不写"应当谨慎处理"这类无从判定的话。写不出可核形式,说明这条还没想清楚,不是文风问题。
- 术语自然成簇时可用子标题分组;单一内聚领域用平铺列表即可。
- **有目录时,它必须是全文第一个 `##` 节**,其中每个术语名称与词条标题逐字一致,一个名称不得拆在两行。
- **每个词条必须是一个段落**:标题行写成 `**术语名**:`,整个名称一处加粗、行内不放别的内容;标题、定义与 `_Avoid_` 之间不留空行,词条之间空一行。全局指令「读项目词汇表 `CONTEXT.md`」按这两条结构只取目录与单条,结构不符就取不到。

## 禁止形态

写入前逐行对照下表,命中任一行即不写进本文件。内容已在归宿里的,本文件至多留一个指针(如 "(ADR-0012)");不在的,先补进归宿。

| 形态 | 归宿 |
|---|---|
| 约束与不变量("凡 X 必须 Y") | 项目 `AGENTS.md`(见全局指令) |
| 做法与步骤 | 产品行为的归 spec,实现的归代码,工作流程的归 skill |
| 本项目实现的标识符:文件路径、类型、函数、常量、字段、CSS 选择器、存储位置 | 代码 |
| 事件经过:发生过什么、曾经怎么错、怎么发现的 | 复盘 |
| 只标何时定的日期("(某日定案)") | 不写;考据归版本历史 |
| 测量数字、计数、"当前有 N 个" | 支撑某条决策的归该 ADR 的来源段,其余归测得它的那段代码的注释 |
| 备选项与取舍过程 | ADR |
| 界面行为细节 | spec |
| 功能的上线状态 | features |

外部系统自己的名字(另一个工具的命令名、配置键、目录名)不算本项目实现的标识符,只在定义或消歧必需时出现。

## 单/多上下文仓库

- **单上下文(绝大多数)**:一份 `docs/CONTEXT.md`。
- **多上下文**:`docs/CONTEXT-MAP.md` 列出各上下文(名称、CONTEXT.md 路径、一句职责)与上下文间关系(谁发事件谁消费、共享哪些类型)。各上下文目录内放各自的 `docs/CONTEXT.md` 与 `docs/adr/`(系统级决策放仓库根的 `docs/adr/`)。
- 推断规则:有 `docs/CONTEXT-MAP.md` 按它找;只有 `docs/CONTEXT.md` 即单上下文;都没有则首个术语敲定时懒创建 `docs/CONTEXT.md`。多上下文时按当前话题推断归属,不明确就问。
- **旧位置**:`CONTEXT.md` 或 `CONTEXT-MAP.md` 还在仓库根(或上下文目录根)时,写入前必须先用 `git mv` 挪进同级的 `docs/`,不得两处并存;只读不写时按全局指令「读项目词汇表 `CONTEXT.md`」读旧位置那份。
