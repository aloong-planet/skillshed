# 任务图查询与执行状态规范

> Pending: 只读任务图查询命令及下述 skills 接入规则尚未实现。本文记录已确认的目标行为，不表示当前能力。
>
> 本模块尚未上线，没有对应功能目录条目；交付时沿用同一 slug 建立功能目录。

## Problem Statement

状态和依赖散落在 ticket 中，模型难以快速掌握整个 feature 的拓扑和阻塞原因。重复维护状态容易冲突；票已关闭不能证明需求完整实现。插票时重编号又会破坏已有引用。

## Solution

由 task-graph.yaml 集中保存任务身份、状态和依赖，以主工作目录中的本地 graph 为执行正本。只读 CLI 显式读取指定文件，展示关系、阻塞和记录详情；skill 负责核对项目、正本、验收证据和状态变更。

需求覆盖清单负责“是否覆盖完整”，ticket 负责“做什么、怎样验收”，graph 负责“依赖谁、什么状态”。首次逐需求核对在 to-tickets 阶段完成，不能推迟到最后收口。

主工作目录指项目明确指定的固定本地目录，不是调用时的当前目录，也不由当前检出的 Git 分支决定。T99 是稳定的收口角色标识，不是一次施工的临时引用。

## User Stories

1. **US-01**：执行者一次查询即可看到所有任务状态、上下游、阻塞和拓扑，不靠逐张读票猜顺序。
2. **US-02**：执行者可以查看单票记录、前置状态、直接及传递下游影响和 ticket 定位。
3. **US-03**：调用者明确选择 graph，并看到实际读取的位置，避免跨项目或 worktree 误读。
4. **US-04**：调用者能获取帮助，参数错误得到明确失败，不发生猜测、自动执行或安装。
5. **US-05**：计划维护者增票、取消、重开时保持身份稳定，不复用已有 ID。
6. **US-06**：执行者只在所有前置的完成状态进入正本后开工；独立任务不被无关在途票阻塞。
7. **US-07**：审核者能定位验收和合并证据，知道“记录 done”不等于“工具验证过真实性”。
8. **US-08**：需求负责人在切票前确认每条独立需求已有明确承兑票和验收条件。
9. **US-09**：收口者通过明确的 T99 完成全 feature 复核，不靠最大编号推断最后一票。
10. **US-10**：维护者只在 graph 更新依赖及状态，不在 ticket 或覆盖表中维护第二份执行状态。
11. **US-11**：使用者查询时不修改数据、不联网、不执行输入携带的指令。
12. **US-12**：旧项目不被自动迁移，GitHub Issue 状态不会在第一版被自动同步。

## Implementation Decisions

### D-01 文档职责

- graph 记录 schema 版本、feature、收口任务标识及任务集合。每个任务有稳定 ID、标题、ticket 定位、status 和 depends_on；完成和取消分别有证据定位及原因。
- ticket 保存任务要求、AC 和验收证据，带 Task ID 和 graph 指针，不独立维护可变 Status、Blocked by。
- 覆盖清单保存需求来源及版本、原子需求 ID、承兑 ticket/AC、计划验证及实际证据。验证结论不是另一份任务进度。
- 证据可通过定位引用，不复制正文。结构合法、票已关闭、表格填满均不能替代真实覆盖和验收。

### D-02 CLI 契约

- 使用 Node.js .mjs，通过明确的脚本完整路径调用，不依赖全局同名 taskctl。
- 包依赖使用 pnpm 管理并锁定，不依赖调用项目碰巧安装的包。
- 第一版只有 status 和 show <ID> 查询；-f/--file 显式指定 graph。
- -h/--help 显示帮助；无参数等同帮助。帮助成功退出，不要求 graph、Git 环境或任何安装动作。
- 未知命令/参数、缺少文件或 ID、冲突参数返回非零退出码及可操作的用法提示。
- stdout 输出正常结果，stderr 输出错误；稳定纯文本，不依赖颜色或交互式提示。
- 没有写入子命令、自动启动、自动调度、独立 validate 命令或自动安装行为。

### D-03 文件定位与正本

- -f 接受绝对路径，或相对于调用工作目录的相对路径；不自动搜索、创建或回退。
- graph 内本地 ticket 路径相对于图所在目录解析；远程 Issue 使用明确 URL，不按标题匹配。
- 输出实际解析的绝对 graph 路径、feature 及可确定的工作树信息；无法确定的信息如实说明。
- 正本保存在主工作目录的 .workings 工作记录区域，不提交 Git，不属于任何 Git 分支；代码合并、拉取或切换分支不承担 graph 状态同步。
- CLI 只读取所指定的文件，不自动 fetch、checkout、merge，也不认证该文件是项目指定的正本。
- skill 开始或恢复任务前，依据目标项目、feature、tracker 约定和 ticket 指针核实主工作目录中的本地 graph，显式传入正确文件；不能只靠 shell 当前目录、分支名、相同文件名或第一条搜索结果。
- 同一项目和 feature 的其它 worktree 通过已核实的绝对 -f 路径读取及维护同一份正本，不把各自的本地副本当作执行依据。
- 临时图副本可用于审查，但副本的 done/ready 不解锁下游。无法定位或核实正本时报告未知，不自动创建或回退到副本。
- 不引入规划 worktree 或同步服务；同机 worktree 直接访问同一文件，不依赖 Git 传播修改。主工作目录被删除、文件丢失或换机器时，Git 不提供该本地图的自动恢复。

### D-04 图、状态与编号

- 只手工维护 depends_on；反向关系、拓扑、ready 和 blocked 均为派生结果。
- 状态为 pending、in_progress、awaiting_acceptance、done、cancelled。
- ID 不代表执行顺序；插票、改标题、调整依赖不重编号，不回收已有 ID。
- T99 保留给收口票，普通任务跳过该编号。收口必须显式依赖其它全部未取消任务，不能依赖“编号最大”规则。
- cancelled 不等于 done，不自动满足仍指向它的依赖。取消须保留 ID 和原因，显式调整受影响依赖和需求归属。
- 新增任务必须同时核对实际上下游、T99 和需求覆盖清单；不能只增加节点而遗漏承兑或收口。
- 采用图规范的多票 feature 必须有明确 T99；单票尚未启用切票图流程时不强制迁移。

### D-05 查询输出

status 显示图身份、总数及各状态数量、所有任务的 ID/标题/状态、直接前置与后继、阻塞原因、稳定拓扑层级、在途和等待验收任务，以及 pending 且全部前置 done 的依赖就绪任务。同一输入顺序稳定，不用编号或文件排版伪造优先级。

show 显示指定任务记录、ticket 定位、前置状态、直接阻塞、直接及传递下游影响、完成或取消信息。默认不加载 ticket 全文、远程内容或证据正文。“受影响”不等于“立即解锁”，仍有其它前置时继续说明阻塞。

依赖就绪只说明所读取图的前置条件满足，不等于已领取、已获执行授权或自动启动。允许推进独立票也不自动授权并行 agent。

### D-06 状态转换与生效

- 新任务 pending；开始后 in_progress；等待验收或合并时 awaiting_acceptance；验收退回修改时回到 in_progress 并记录新的待验证范围。
- done 要求实现、规定检查及验收通过，且对应交付 PR 已合并。完成记录引用可复查的验收及合并证据；CLI 不联网验证真实性。
- 实现 PR 合并且规定验收通过后，直接在主工作目录中的本地 graph 记录已核实的 done，再运行查询校验。正本更新并通过校验后，前置全部完成的依赖票即可推进；不提交额外的 graph 状态更新 PR。
- 不在实现合并前预填有效 done。in_progress、awaiting_acceptance 等状态也直接更新同一本地正本，无须等待代码提交或合并。
- 本地正本更新可能遗漏或与其它执行者并发；不能把 pending 当作“没有人在做”，第一版不防重复领取或并发覆盖。
- 前置已全部完成的独立票可以推进，不要求等待其它无依赖的在途票。
- 取消须有明确的范围决策，保留原因。重开或新需求使原结论失效时，重判前置、证据、下游和 T99，保留旧验收历史而非直接复用结论。
- 对已知使原前置或完成结论失效的待合并变更，不能借本地图中尚未修正的 done 绕过核对继续工作。

### D-07 Skills 接入与范围

- to-tickets：切票展示和发布前完成原子需求双向核对，给每条需求明确承兑票及 AC，再核对依赖图。改动面枚举不能代替逐需求覆盖。
- to-tickets：生成稳定身份、图和 ticket 指针；更新现有重复状态/依赖及按编号收口的模板规则。
- 接入时明确主工作目录和正本定位，落实 .workings 工作记录不提交的约定。graph 只作为当前任务状态与依赖的正本，不把其中的记录或其它历史施工材料直接当作产品现状证据；现有已跟踪文件的迁移仍需另行明确范围。
- implement：开始和恢复前 status/show；任何增删改、状态转换和依赖变更都更新 graph，再查询校验；执行依据遵守本地正本更新及校验规则。
- features-catalog：逐票同步行为文档；T99 做全量一致性、跨票组合和逐需求证据复核，不承担第一次拆解检查。
- 第一版只做通用工具与 skills，不迁移旧项目，不自动重编号或清理旧票。
- GitHub Issue 可作为任务内容载体；第一版暂不接入开闭状态、标签或平台依赖同步，平台状态不作为执行正本。

## 失败模式与边界

- **B-01 帮助或首次调用**：无参数与帮助均成功显示用法，不要求图存在，无写入或网络副作用。
- **B-02 参数错误**：未知、缺失和冲突参数明确失败，不隐式选文件或任务。
- **B-03 改变调用目录**：外部相对参数与图内相对引用使用各自基准，不混用。
- **B-04 同名图或陈旧副本**：显示实际身份；skill 核实最新正本，不能从相同名称推导“正确且最新”。
- **B-05 文件不可读**：缺失、无权限或目录代替文件均非零退出，不寻找替代文件或创建空图。
- **B-06 解析失败**：非法 YAML、未知版本、字段类型错误、必填缺失、重复键或 ID 明确报错，不静默覆盖。
- **B-07 无效边或循环**：未知依赖、重复边、自依赖、环路明确失败；环路给出可理解的路径，不输出可信 ready 列表。
- **B-08 缺少收口**：多票图为空或无有效 T99 不能声称完成；插票后漏掉 T99 依赖必须报错。
- **B-09 查询未知 ID**：失败而非模糊选择、新建或回退。
- **B-10 多个前置**：只完成一项不解锁其它前置仍未完成的下游。
- **B-11 取消和恢复**：取消不完成依赖；恢复重新核对前置及证据。存在未处理的取消依赖时明确显示阻塞，不过滤掩盖。
- **B-12 实现已合并但 graph 未更新**：不解锁下游；关闭 Issue 或其它 worktree 的图副本 done 不能代替正本更新；本地正本更新并校验后无须再等待状态提交。
- **B-13 证据问题**：必需证据定位缺失是记录错误；存在定位不代表内容已验证，旧证据不能自动承兑新范围。
- **B-14 状态矛盾**：done 仍依赖未完成任务时报告矛盾，不绕过前置；结构合法也不能证明没有遗漏真实依赖。
- **B-15 中断及并发**：恢复重查正本和实际在途工作，查询只是读取时结果，不提供锁、并发编辑合并或持续有效保证。
- **B-16 收口后加票**：同一 feature 的批准增量使原结论失效时重开受影响票和 T99，更新覆盖，不复用 ID 或删除旧证据。
- **B-17 输入携带能力**：YAML、标题、URL 和引用均为数据，不执行脚本、模板、命令或提示指令，不自动渲染 Markdown、打开链接、读取引用或联网。
- **B-18 畸形或过量内容**：解析遍历失败明确退出，不无限展开循环引用，不把部分结果当成功；终端控制字符不能改变展示语义。具体容量边界在实现验证时明确，不承诺无限输入。
- **B-19 环境缺失与只读**：缺少运行时/依赖时提供指引，不自行安装；有效及无效查询均不得修改输入、缓存、票或仓库。
- **B-20 旧票及平台差异**：不自动迁移或根据 Issue 关闭推导 done，不声称同步成功。
- **B-21 ticket 重复字段**：skill 在生成、改票、验收时核查可变字段的职责；不得把历史引用或普通正文中的状态词当作另一份结构化状态。
- **B-22 正本丢失或目录迁移**：换机器、清理主工作目录或文件丢失时，不声称可从 Git 恢复，也不从旧副本或全部关闭的 Issue 自动重建 done；迁移后先确认新的正本路径和现有证据，再继续执行。

## Testing Decisions

主要公开测试边界是 CLI 进程：通过参数、实际工作目录和临时 YAML 输入，独立检查退出码、stdout/stderr 和输入是否变化。使用真实解析与文件读取，不通过私有内部对象或调用次数代替外部行为。

采用可手工核对的链、分叉、汇合、取消和环路样本；预期关系不调用被测算法生成。路径测试必须真正改变工作目录。帮助、错误与成功均穿过相同公开入口，验证无写入、无网络行为。

skill 的需求承兑、正本选取、验收真实性和合并后更新纪律另做工作流场景验收。至少覆盖多个 worktree 访问同一本地正本、误用图副本、正本缺失、实现合并后本地记录 done 即可生效而无须状态 PR、取消前置及插票漏收口；保留实际输入、动作和结果，不能以规则存在、表格填满或 CLI 单测通过代证。

本轮仅定义命令及纯文本输出的数据口径，不涉及页面、视觉控件或样式，故不新增视觉原型；后续仍需核对实际 CLI 输出是否可理解。本轮未执行产品测试。

## Out of Scope

- 写入子命令、自动调度或启动任务、全局同名可执行文件安装。
- 自动找图、创建图、安装依赖、拉取 Git 或切换分支。
- 规划 worktree、跨机器或副本自动同步、自动备份恢复、防重复领取和并发写入保护。
- graph 的 Git 提交、状态更新 PR 或依靠分支合并传播任务状态。
- 联网验证证据、GitHub Issue 状态/标签/依赖同步。
- 旧项目迁移、按执行顺序重编号或复用 ID。
- 用 DAG 校验替代语义依赖检查、完整需求覆盖或真实验收。
- GUI、常驻服务、数据库、额外写入 API 或独立 validate 命令。

## Further Notes

正式实施时需同步更新现行 skill 模板；本文不表示模板已经修改，也不静默替代仍在使用的旧流程。本地正本不受 Git 版本管理，也不提供并发写入保护或自动恢复，是当前方案明确接受的边界。
