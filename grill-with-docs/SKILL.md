# 第 1 步:调研 = ① 事实坐实 + ② 需求对齐

动手前两件事都要做。**未达成共识前不动手**——需求不明确宁可继续问。

## ① 事实调研(客观事实,自己查,不拿来问用户)

- 有参考实现或依赖库时,先读它的**真实代码与类型定义**坐实事实(可派 Explore agent 深挖 + 自己核对 .d.ts)。
- 基于**最新版本**调研,不用旧版。
- 产出带 **file:line 证据**的结论,明确区分「确认」(读代码/实测坐实)与「推断」(设计选择/猜测)。
- 能从代码/环境查到的一律自己查;**只有决策才问用户**。

## ② 需求对齐(意图/决策归用户)

运行 `/grilling` 会话(一次一问、每问附推荐答案、走决策树每个分支、共识前不动手),
同时按 `/domain-modeling` 维护领域模型:术语一敲定即写 CONTEXT.md;决策定形且过三门槛时,当场 offer ADR(格式见 domain-modeling/ADR-FORMAT.md,含三态规则——证据未闭环的落"提议"态)。
