# 调研 = ① 事实坐实 + ② 需求对齐

动手前必须做完 ① 与 ②;② 必须把仍然成立的决策全部问完——包括前面的答案引出的新决策——并与用户达成共同理解。

**事实与决策分流**:每个要向用户提的问题,提之前必须先判定:能从环境(文件系统、代码、工具)查到的事实,按 ① 自己查,不拿来问用户;决策全部归用户,按 ② 逐项摆到用户面前等答案,不替用户拍板。

**归属仓库**:计划的产出(代码、文档、skill、配置)所在的 git 仓库;产出不在任何 git 仓库里的,计划没有归属仓库;产出分在几个仓库的,以哪个为归属仓库先与用户定下。

**共识不得只留在对话里**——上下文一蒸发,下一轮谁也复现不出当时定了什么。有归属仓库的,术语按 ② 落进 CONTEXT.md,够 ADR 门槛的决策按 ② 落 ADR;没落进这两处的需求、边界与决策,以及没有归属仓库时敲定的术语,每拍定一条,必须当场写进对齐记录 `alignment.md`(位置与 `<slug>` 见下两条),一条一个列表项,写明拍定的内容与用户确认它的原话。这份记录的标题写为「需求对齐记录」,按 [产物固定名称](../repo-scaffold/artifact-names/grill-with-docs.md) 书写;它记的是拍定的事项,不得当作调研文档存放。**判据**:本轮拍定的每一条,说得出它此刻躺在哪个文件里。

- **对齐记录的位置**:有归属仓库的,写在该仓库的 `docs/.workings/<slug>/alignment.md`,不得拿它代替 spec;没有归属仓库的,写在 `~/requirements/<slug>/alignment.md`。
- **`<slug>`**:改动的是某个产品功能的,取它的 spec 的 slug(与 `docs/specs/` 的文件名对齐);其余取概括本计划的短名;尚未定的先与用户定下。

## ① 事实调研(客观事实,自己查,不拿来问用户)

- 有参考实现或依赖库时,先读它的**真实代码与类型定义**坐实事实(可派 Explore agent 深挖 + 自己核对 .d.ts)。
- 依赖库必须按项目实际使用的版本调研(锁文件或已安装的版本);尚未引入的按准备引入的版本,决策涉及升级的另查目标版本,结论都标明版本。
- 产出带出处的结论:出处是文件的给到 **file:line**,是网页或外部资料的给到链接,是实测的给到所跑的命令与结果;明确区分「确认」(读原文、读代码或实测坐实)与「推断」(设计选择/猜测)。
- **否定结论要换手段**:样本能证明"有",证不了"没有"——凡结论要写成"只有这几种形态"「不存在 X」,必须换一种不依赖覆盖率的手段(全量扫描并计数、穷举类型或枚举全集、走全历史),做不到就如实写"本次采样未见",不写"不存在"。这类否定结论错了,后面没有哪一步会来纠正它。
- **别人写下的事实同样要坐实**:既有注释、文档、测试记录的是"当时有人这么认为",不是"现在仍如此";凡要作为本次决策前提的,当场用当前代码、原始资料或实测复现一遍,复现不出的按未确认处理。

## ② 需求对齐(意图/决策归用户)

有归属仓库的,同时按 `/domain-modeling` 维护该仓库的领域模型。

设计问题在对话里拍不了板(证据不在桌面上)时,不得硬拍:原型能产出所缺证据的,先调 `/prototype` 拿到证据再拍;产不出的(如要靠上线或外部实测的选型),必须向用户写明缺哪项证据、要靠什么取得,由用户决定先定方向还是暂缓,先定方向、有归属仓库且够 ADR 门槛的按 `/domain-modeling` 落「提议」态。

### 分批提问

不一次一问,也不一股脑全抛。按依赖关系分批:

1. 把余下的用户决策画成依赖图:谁的答案会改变谁的问法、选项或存在性。
2. **只实例化当前批**:当前相互独立的决策**全部**并成一批提问,批内数量不设上限;后续决策停留在图节点上,**不预写问题文本**。
3. 批内按主题归组排序,别按发现顺序乱堆。
4. **每批答完先回炉再出下一批**:用本批答案更新依赖图——砍掉失效分支、长出新分支、重推下一批每问的问法/选项/推荐答案。前一批的答案是下一批问题的输入,不是并行无关的两张清单。不重复已答。
5. 当前只剩一个独立决策时直接单问,不硬凑批。

### 每问的信息密度(分批不稀释)

每个问题必须带全:

- 为什么现在要做这个决策、已知约束;
- 一个**推荐答案**及推荐理由;
- 每个选项是什么、各自的收益/代价/风险/后续影响。

可枚举选项的批次,当前工具提供 AskUserQuestion 的用它提问(推荐项放首位并标注),不提供的用文字提问;开放式问题用文字提问,可与工具批次混用。工具单次最多 4 问是渲染限制,不是批上限:同批超过 4 个时按主题分组拆成连续多次调用,调用之间不回炉、不等前一组答案改后一组问题——回炉只发生在批与批之间。

### 选项不夹带次级决策

选项描述里不得捆绑未单列的独立决策(范围限定、依赖引入、"顺便不动 X"之类)。用户选中选项只构成对**问题本身**的决策;描述里夹带的限定若日后要当决策引用,必须在当时单独摆出来问。
**判据**:写完每个选项自查——"这段描述里,除了在回答本问题,还替用户定了什么?"定了就拆成独立一问,或删掉不写。
**引用侧对称的判据**:把某条约束当授权引用前,回到出处确认它是**被单独问过并选定的**,还是当初夹在某个选项描述里的——后者只是当时的实施说明,不构成对后续改动的约束。
