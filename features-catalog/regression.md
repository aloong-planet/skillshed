# 交叉回归

本文适用于执行文档一致性回归的一方(下称执行方):按 [SKILL.md](SKILL.md)「文档一致性收口」节被派出的子 agent、按该节「自己执行」一条自己执行的主 agent,以及按 SKILL.md「全 feature 收口」节重跑三个阶段的收口票会话。入口:[SKILL.md](SKILL.md) 的这两节。

## 执行方的边界

- **本轮的范围**:被派出的,本轮指从交接给的分叉点到交接给的 commit 的 commit 范围;交接写明了修复的 commit 范围的,本轮改为该范围。按 SKILL.md「自己执行」一条执行的,本轮指从分叉点到当前 `HEAD` 的 commit 范围,加上工作区里未提交的改动;修复发现之后重跑的,本轮改为修复的 commit 范围。按 SKILL.md「全 feature 收口」节执行的,范围按该节。
- **只改文档**:执行方只得改写文档(界定见 SKILL.md「交回与文档的界定」的「文档」条),把其中的陈述改到为真;不得改动其余任何文件。一处不一致要靠改文档以外的文件才能消除的,记为发现。
- **不写报告**:不得把行集、各行的结论或发现写成文件;发现与判过的陈述条数、所跑的检索,按 SKILL.md「交回与文档的界定」的「交回」条交回,按「全 feature 收口」节执行的交给本会话处置。
- **被派出的子 agent 另须遵守**:不得提交,也不得再派子 agent 执行本文的任何部分;回归结束时按 SKILL.md「交回与文档的界定」的「交回」条交回。
- **项目里还有 `docs/features/` 的**:检出里存在 `docs/features/` 目录、且其中有 Markdown 页时,必须记一条未能解决的发现,写明迁移办法——把该目录下每一页写着而同名 spec 没写的内容补进该 spec,把指向该目录及其文件的引用改指对应的 spec,再删除该目录;何时迁移由项目所有者决定。迁移完成之前,不得改写该目录下的文件,也不得拿任何陈述与它核对:它不进三个阶段的任何行集。

## 回归

回归的基本动作只有一个:**把一句陈述与它的对照端并置,判它现在还真不真**——对照端指该句派生自、复述着或引用着的那个东西:实现、同一事实的另一处陈述、索引行、守它的门禁、被它枚举的成员集。判一句陈述必须读对照端的原文,不得以文件存在、链接打得开或对照端的状态写着完成代替。

**施工记录不是依据**:需求、当前产品行为、决策与术语分别以 spec、ADR、`CONTEXT.md` 为准,不得拿施工记录代替它们判一句陈述;证据与这些文档的描述不符时,必须查明差异,不得只因文档层级而否定实际观测。

**查验对象含 docs/ 之外的声明面**:凡对用户陈述产品行为的载体都在查验之列,界面文案字典、各语种 README、包元数据与 docs/ 下的文档同级,不因存放为代码而豁免——它们改起来属代码 diff,查起来却没人当文档查,于是成为最久没被读过的一批。字典是否入查按能力 `i18n` 判定(`capabilities.toml`)。

一句陈述的真值被本轮弄坏,只有三种方式,按**本轮 diff 覆盖了这对核对的几端**分成三个阶段。三个阶段只是取材规则不同,不是执行顺序(执行见「停止条件」,取出顺序不限):

| 阶段 | 谎怎么产生 | 行集从哪来 |
|---|---|---|
| 一 · 逐句核真 | 陈述与对照端都在改过的文件里,改了一端忘了另一端 | 本轮改动的声明面文件清单 |
| 二 · 关系对读 | 陈述在没改的文件里,它的对照端被改了——单看每一端都正确,并置才现身 | 关系目录(见该节) |
| 三 · 事件核销 | 两端都没被改,陈述引用的事实被本轮改变了 | 本轮事件清单(见该节) |

三条取材规则互相顶替不了:**跑多少遍阶段一也照不到后两阶段的行**——不是查得不够仔细,是那些句子根本不在它的取材范围内。范围的上界同样由取材规则给出,**不做全仓审计**:每个阶段只判自己行集里的行,行集之外的句子不看;查漏的救济不是扩大范围重扫,是按「发现之后」的归因规则补目录或事件清单。

**行集里的每一行都必须判出结论,不得只看命中项**:只看命中项时,「漏看了」与「看过判合规」无从分辨,而前者恰是要防的那个。**行集按上表机械派生,不得由执行者临场想**:想出来的清单必缺项,而缺的那项不会自己现身。某阶段行集为空的,必须说得出它为空的派生依据。

**用检索派生行集或核对陈述时,检索词必须覆盖被检文件实际用到的每一种语言**:同一事实用另一种语言写成的句子与单一语言的检索词互不匹配,漏掉的那批不报错,输出与「别处没有这种说法」逐字节相同。**判据**:先用一条按文字系统统计的命令(如文件里有没有汉字、有没有拉丁字母)一次得出本次检索范围用到的文字系统,不得为此逐个读文件,也不得按项目声明的工作语言推断(工作语言只约束新写的产物);一种文字系统只对应一种语言的,即得出该语言;为多种语言共用的(如拉丁字母),必须另行确定用到其中哪几种(按 i18n 字典的语种目录、文件名里的语种标记),确定不了的记为发现,不得把它当作其中一种;再为每个检索词写出它在每种语言里的说法(术语、译名、缩写)并逐一检索,交回的检索里每种语言各有一条。缺了某种语言的检索,不得据以对用该语言写成的句子下结论。

**检索与读取不得被默认过滤或失败悄悄缩小**:枚举与内容检索必须显式包含隐藏项与被忽略的文件,不得拿工具默认过滤后的结果证明某处没有某句话;已知路径必须直接读取,不得以目录检索没有命中判它不存在。访问、读取或枚举失败、输出被截断的,必须补查;补查不了的,把没有核实的范围记为一条未能解决的发现,不得据以判任何一行。

### 阶段一 · 逐句核真(两端都在改过的文件里)

对本轮触碰的每一份声明面,逐句问「它现在还真吗」,并按下列各对核对:

1. **spec ↔ 实现**:`docs/specs/<slug>.md` 描述的是最终实现、写全了本轮用户能感知的行为变化吗?按 `/tdd`「覆盖来源」节的覆盖清单,其中每一项都有测试或已标注缺口?
2. **ADR ↔ spec**:本次落的 ADR 结论没有被 spec 反向表述;spec 里够门槛的决策已落 ADR 并改为引用编号。
3. **CONTEXT ↔ 全体**:新术语已落 CONTEXT.md、新不变量已落项目 AGENTS.md,且本次回归涉及的每一份文档用同一套词(不出现同义异名)。

### 阶段二 · 关系对读(另一端不在 diff 里)

本阶段要核的陈述从不出现在 diff 里(被改的是它的对照端),所以行集只能靠下面的目录去取,不能靠"顺手看见"。关系目录:

- **文件 ↔ 它的索引行**:凡带 README 索引的文档目录(specs、ADR、复盘等),新增、改名或改动一句话时索引同步改。漏一行,那份文件在只读索引的人眼里等于不存在。
- **规则 ↔ 模板及生成文档**:必须让模板的生成指令引用最先出现的规则定义,不得在模板中另维护一套手写规则。规则改变时,必须检查生成指令的引用是否仍有效,并更新本轮范围内按该规则生成的文档说明;成品文档必须让其读者无需访问本机 skill 即可理解。
- **一个事实 ↔ 它在别处的陈述**:必须从交接、本轮的实际改动与运行结果定出本轮变化了的事实,再为每个变化了的事实检索陈述它的全部文档句子,各列为一行并完整读取受影响的内容;不得只按改动过的文件或固定的关键词限定检索。
- **规则 ↔ 守它的门禁**:本轮若有规则由门禁守,核对门禁的检出面是否覆盖该规则的全部形态;覆盖不到的部分记为发现,写明覆盖不到的是哪些形态;加宽门禁还是写明它靠人守,不由执行方定。**门禁绿不证明规则被守住,只证明它查的那部分绿。**

**关系目录是开放的**:以上是至今观察到的,不是全集;增补的触发条件见下方归因规则。

### 阶段三 · 事件核销(两端都不在 diff 里)

必须按本轮已发生的事件建立清单,不得只按文件改动面取材;开工时先列出已知事件:取自本轮的 diff、票与施工记录目录里的文件,被派出的另取交接写明的事件,其余执行方另取自己会话里发生的事件;后续发生或发现的事件必须补入,并按「停止条件」处理。能用命令枚举的,检索式随交回给出。必须检查以下事件类别:

- **某个可枚举维度的成员数变了**(支持的数据源、平台、语言、渠道等)→ 该维度的枚举式措辞全部复查。**枚举式措辞 = 把成员逐个列出、或拿成员数说话的句子**;成员数一变它们同刻成谎,而没有任何一处代码 diff 会碰到它们。**按位置与成员一一对应的平行结构同样计入**——耗时表、默认值表、图标表这类按下标对齐的数组既不列成员名、也不报成员数,按「哪里写着成员名」或「哪里断言了数目」去检索都命不中它;少一项不报错,只让最后一个成员取到空值,再算下去整条链变成非数。**判据**:检索该维度时,除按成员名与成员数各检索一遍外,再问一遍「有没有另一个结构靠下标与它对齐」,答得出就把那个结构的长度一并核对。项目有对应门禁的(能力 `enumeration-wording-gate` 已启用,且该维度在其 `source` 所指门禁的检出面内),引用其本次运行结果、不重复人扫——**前提是该门禁的覆盖面已在阶段二核过**,覆盖不到的形态仍须人扫,否则门禁的绿会替它没查的那部分背书;没有门禁的人工扫一遍,并把「该不该为它建门禁」作为一条发现提出。
- **范围内有 `Pending:` 注记** → 逐条问「本轮是否使它到期」;到期的按 `/to-spec` 的 Pending 条款当场处置,不得留到下一轮;处置需要新决策的,按「发现之后」节办。
- **本轮新拍了通则** → 报出它的正本落在哪一层(项目 AGENTS.md 不变量 / ADR / 写作层 skill)。只活在代码注释、原型或施工记录里的视为未落地:正本该落在检出里的文档(项目 AGENTS.md、ADR)的,当场补写;该落在检出之外(写作层 skill)的,记为发现——那三处都不在下一个写代码的人的必经之路上,规则待在那里约束不到任何人。
- **验收反馈、缺陷修复或工作状态改变** → 检出里陈述这件事所改变的事实的句子(以它为条件的 `Pending:` 注记、索引行、README 里的现状说明)各列为事件行;不得因这些文件不在 diff 中而跳过。施工记录里的票与需求覆盖清单不因这类事件改写。

### 停止条件

必须将三个阶段已派生的行放入同一个工作队列;后续新增事件或关系产生的行也必须入队。

- **收敛判据**:必须逐项处理队列;判为无需改动的不产生新项,改动后必须将改后文本与受影响的关系端重新入队。队列为空后,必须再从交接、本轮的实际改动与运行结果核对一遍相关文档的现状是否与实际结果一致,把新发现的事件或关系按本节入队处理;没有遗漏且队列为空时才可结束核对,不得凭访问次数推断收敛。相同规则组合导致反复改写时,必须把冲突记为发现并按「发现之后」处理;阻断未解决不得宣称完成。
- **取出顺序不限,除非某一行自己写明了前提**(如引用门禁结果的那行):写明前提的,前提那行先处置。
- **事件行去重**:同一事件的事实、适用范围和对照端均未改变时,必须复用已有的行,不重复入队;任一发生变化或发现新事件时,必须新增或重新开启对应的行。事件处置产生的文本改动必须按本节「收敛判据」回查。
- **重查的是改动的波及面,不是全集**——全量重跑绝大部分是空转。

### 发现之后

发现的不一致,能靠改写文档消除的**当场修**;修不了的(要改文档以外的文件,或需要新决策)记为未能解决的发现,写全哪句陈述与什么不一致、要靠改什么才能消除,不得自行裁决。

**事后又发现东西,先归因再动手**:该项在行集里而判错 → 重判该项;**该项不在行集里 → 关系目录或事件清单缺了一条:本轮先按缺的那一条补跑受影响的那部分,再把缺的这一条记为发现,写明它该补进本文的哪个目录**。补的是镜头,不是力气——"再多查一遍"对不在取材范围内的句子永远无效。
