# Skill 写作规范

适用于一切 skill 的新建与修改:SKILL.md、其引用文档、资产内的说明文字。

**条文的单位定死**——一个列表项、一个独立段落、表格的一行,各算一条;标题与代码块的语法内容不算,**代码块内的说明文字**(模板占位符里的指导语、代码注释)照常成条——算不算条按内容定,不按围栏定;同一空行块内以硬换行并置的行各算一条,行尾不是 。!?;: 及其后的引号、括号、强调星号的行是排版折行,与下一行同属一条;列表项的缩进续行随其列表项。

## 1. 条文必须是命令式的明确语句

- 用「必须 / 不得 / 一律 / 缺任一则不得 X」陈述;主语是执行者的动作,不是现象。
- 每条规则自带可执行判据:读者无需任何额外上下文即可判断"此刻是否违反"。
- 不得用偏好代替判据:条文在几种做法里规定取哪一种时(「取最高层」「越少越好」「优先 X」;带了条件的同样适用,如「判为自伤的,进清单缓办」),必须试举一个满足它全部条件、照它取却会选错的情形。举得出,就把条件改成真正决定取舍的因素;改不出的,删掉这条偏好,交给执行者按情形判断——偏好把条件没写到的情形一律推向同一边,而那一边只在写它的人想到的情形里是对的。
- 不得用现象描述代替规则:"X 会发生"不是规则,"不得做导致 X 的 Y"才是。
- 凡判据要求"举得出一个例子",先找它的可枚举结构改成照表核对:构造例子依赖灵感,灵感不可复现;对齐表只依赖眼睛,且检出率更高。
- 指代与本 skill 自定义的术语,使用处必须有锚。**判据**:在上文指得出锚点——指代词的锚是一个名词性词组,术语的锚是给出其判据或构成的定义条文(仅出现名字不算)——把锚代入该处后句子仍读得通、意思不变。锚不存在即失锚,锚只在后文即倒置,代入后意思变了即同名异义。带显式出处的引用(「按 §N 的…」「见某节」)不算倒置——它自带定位,不需要上文。
- 泛化或收紧措辞时,原有的限定词不得丢。**判据**:去掉它后试举一个「符合新表述、但机制不成立」的反例——举得出,它是条件,必须留;举不出才是载体,可以删。

## 2. 实例必须抽象成规则后才准进入

- 促成规则的事故先抽象:写进 skill 的是抽象后的规则,不是事件经过。
- 抽象完成的判据:删去日期、**事发**项目名、当事文件名后,条文仍完整、仍可执行。删的是事故的身份,不是被测技术的名字——后者可能是判据的前提,按 §1 的限定词测试判去留。
- 事件叙事另有归宿:项目复盘文档或 memory;skill 内不得保留"某日发生过某事"式内容。
- 例外必须写成触发条件("仅当 A 且 B 时可 X"),不得写成豁免叙事。**软化词(一般、通常、多半、尽量、原则上)出现在规则里即违反本条**:要么写出例外的触发条件,要么删掉软化词——它把例外藏了起来,读者无从判断自己是不是例外。出现在理由或举例里不算。
- 理由允许保留,但必须是**机制性**的且并入条文本身;不得以括号轶事、事件叙事的形式追加。
- **不加纯出处标记**:「(某日定案)」这类只标何时定、不承担任何判据前提的日期标注,一律不写;既有的,触碰其所在条文时一并删。何时定的不改变执行者此刻该做什么,考据归版本历史。作为实测数据适用前提的日期不算出处标记,按下一条办。
- 支撑技术判断的**实测数据**(量级、比值、行为差异)视为判据的一部分,可以保留;须标注其适用前提,不得叙述取得它的过程。**判据**:能在同一处指出哪句话是前提即合规,不要求特定句式、也不要求单独成句;指不出才算缺前提。

## 3. 条文的位置与顺序(写入时就定)

**同一条规则在两处各写一遍即为缺陷**,不因两处措辞一致就放行——一致只是此刻一致,改了一处另一处不会跟着变,而改的人不会想起去查另一处。**判复述**:删掉其中一处,留下的那处是否仍使规则在被删那处的适用范围内完整可执行?是 → 那处是复述,改成指针或删掉。判为复述前,必须并列写出两处各自约束的对象、时点与条件,各引原文,原文没有限定的写「未限定」;留下那处每一项都等于或宽于被删那处,才算覆盖。写不出这份对照的,不得判复述——措辞相同而适用范围不同的,删了就丢规则。引用旁边概括被引用处结论的一句话,按 §4「每个引用都必须带来读者在此处缺的东西」一条判去留。

### 归哪个 skill、写在哪个时点

- **写进执行它的 skill**:问条文「它约束的是哪个动作」,必须写进执行这个动作的 skill;别的 skill 要用它,只得放指针,不得复述。**判据**:按路径列出这个动作必须在哪些时点执行——路径包括被每个调用方调用与被单独激活;一个时点算必须执行,当且仅当同一路径上它之后再没有执行这个动作的时点,或留到之后执行会出错。在每个必须执行的时点都载入的 skill 只有一个时,它就是执行这个动作的 skill;否则就是几个 skill 共同执行。动作由几个 skill 共同执行的,必须写进产出该动作所约束对象的那个 skill(约束测试怎么写的归写测试的 skill,约束原型的归原型 skill);对象也由几个 skill 共同产出的,写进它们都要求读取的同一份引用文档。动作由委派出去的子 agent 执行的,必须写进子 agent 载入的 skill——子 agent 只读得到自己载入的 skill,写在委派方的条文约束不到它。不论写进哪里,每个必须执行的时点都必须读得到它:写在那时载入的 skill 里,或写在那个 skill 要求读取的 skill 或文件里。
- **写在触发时点**:条文要在某件事出现后才执行得了的(测试已写成、改动已合并之类),必须写进那件事出现的时点,不得写在更早的时点。**判据**:照条文执行要用到的东西(代码、测试、运行结果、记录),在该时点是否已经存在;不存在即写早了——那时的执行者手里没有它,读了也执行不了。
- **不加例外迁就另一个 skill**:两个 skill 对同一件事各写了条文的,不得在一方加例外去迁就另一方,必须按上两条判出归属并照办——加了例外,两处仍各写着这件事,改了一处另一处照样不会跟着变。
- **后面的检查代替不了前面的停顿**:条文要求在某项工作之前停下的(先经用户确认、先回写 spec 之类),不得因为后面的时点另有检查能发现同一问题就删掉或挪后——检查发现时,依赖它的工作已经做完。

### 入哪个节、怎么排

**节标题是一个断言**:条文挂进哪个节,位置就在替它声明适用面。

- **入节前先比适用面**:问新条文「它在约束什么」,再拿同一个问题问目标节的标题与引言;条文的适用面不落在节的适用面之内,不得入该节——嵌套时逐层都须成立;比节宽的上提一层(外层节或文首),无处可去的先立节。不得因为"正在编辑这一节"就把条文追加在节尾——增量修改的默认动作恰是顺手追加,位置从来不是判断的产物。
- **流程类条文按执行顺序排列**。**判据**:给每条标执行序,与书面序两列对照,乱序即违反本条。

## 4. 跨 skill 的引用与依赖

本节的**引用**,指条文点名别的 skill、以路径指向别的 skill 目录里的文件,或指向全局指令的某一节。

**调用方与被调用方**:skill A 的条文要求执行者调用 skill B 或按 B 执行时,A 是调用方,B 是被调用方。

- **被调用方不得引用调用方**:被调用方的正文、引用文档与选择器(§5),都不得引用调用方的步骤、跳过判定或归属,也不得写明谁会调用它。被调用方按自己的条文执行,与谁调用了它无关;引用调用方的步骤,调用方一改就过期,而改调用方的人不会去查被调用方。下列三种不算反向引用:
  - 引用多个 skill 都要求读取的共享文件(产物名称表、日志格式说明之类),而不是调用方的步骤或判定;
  - 选择器点别的 skill 的名字,是为了把不该选本 skill 的情形引开(如「需求仍待澄清时使用 X」);
  - 要求执行者调用调用方,去做调用方自己的某部分工作(可点名该部分所在的节)。按调用方的某节判定本 skill 自己做不做,不在此列。
- **不得拿别处的执行当本处的依据**:别的 skill、它产出的记录、全局指令流程里的别的步骤做没做、会不会做、归谁做,都不得作为本处做或不做什么的依据——不论谁先谁后、谁调用谁、点没点名。**判据**:设想那一方这次没有执行(本条自己要求执行它的除外),或改了自己的做法(被引用的节被删或改名不算),本条要执行者做的事是否仍然对;不对即违反。调用它、按它定义的规则或格式做本处的事、核对它的产出,都经得起这一问。以它的产出为前提的条文,没写缺了这份产出怎么办、照字面执行会得出「已满足、没有问题」的结论,或当作有这份产出照常往下做的,即为不对;写明了缺失时怎么办的(停下、改用别的来源),不算。这一判只在存在一条执行到本条、却拿不到这份产出的路径时做;被调用方的路径要算上被任何调用方调用、以及被单独激活的情形。
- **改掉违反上两条的写法时,不删规则**:引用了调用方的,删引用;拿别处的执行当依据的,删依据;没写缺了前提产出怎么办的,补写。规则本身按 §3「归哪个 skill、写在哪个时点」归本 skill 的,必须留下;归别处的,必须移到归属处。
- **每个引用都必须带来读者在此处缺的东西**:调用方引用被调用方不受「被调用方不得引用调用方」一条限制,与其余引用一样按本条判去留。条文里有引用的,必须先把引用之外的每一项要求逐项列出,各按 §3 开头的「判复述」与被引用处对照,判为复述的按 §3「写进执行它的 skill」一条删去。唯一可以留下的复述是一句概括被引用处结论的话:不列它的分支、步骤与判据,且在此处的适用范围内与被引用处说的一样——不多出被引用处没有的限定或要求,也不丢被引用处就这件事写明的例外与条件(被引用处有例外的,不得写成「一律」)。然后对引用做删除测试。**判据**:被引用处不常驻上下文的,先读它,列出它就此处这件事写明的例外与条件,其中有此处没写出的,读者只能经这个引用得知,引用必须留下。其余情形删掉这个引用(连同「按 X 执行时」这类点名别的 skill 的限定语),读者若仍知道此处该做什么、按什么判,它就是多余的,必须删。只提醒遵守全局指令里某条规则、不带别的内容的引用一律多余:全局指令常驻上下文,删掉它规则照样生效。

## 5. 选择器(frontmatter)的写法

**`description` 与可选的 `when_to_use` 共同构成选择器,下列条文对两者各自生效——唯「做什么」一项只要求 `description` 写明,`when_to_use` 按其定义只补触发场景。** 写了 `when_to_use` 就必须与 `description` 分工:只补 description 没覆盖的触发场景,不得复述它已经说过的话——两个字段都常驻上下文,复述一遍等于把同一份匹配预算花两次。

- 必须用第三人称陈述;出现「我 / 你」即违反。
- 必须同时写明「做什么」与「何时触发」,触发条件用具体场景词;只写用途不写触发,或用「帮助处理…」式空泛措辞,均视为未完成。
- 不得概括正文的规则、流程或步骤;流程只准在正文里出现。**选择器只负责被选中**:两个字段都常驻上下文,唯一职责是让模型从全部可用 skill 中选中该用的那个;正文在 skill 被触发时必定完整加载,不需要在此预告。写进流程摘要要付两笔代价——一是占掉本该用于匹配的字符、从而稀释触发关键词的密度,二是把执行指导放进一个只在「要不要加载」那一刻起作用的字段。(依据:官方 Agent Skills 文档对 description 的定位与 progressive disclosure 机制。)
- 判据:遮住正文只读选择器,应能回答"什么时候该用它",且推不出"具体怎么做"。

## 6. 自检(两阶段,阶段一收敛后才准进阶段二)

### 通则(两阶段都适用)

**两种用法,只差范围**:改完自审时,范围由本次改动圈定;**审一份没动过的 skill 时范围由文件圈定**——阶段一过全部条文,阶段二拿每一条问「它在约束什么」取对象。后者不得只盯可疑处抽查:抽查漏掉的正是"两条都没被怀疑、合起来才冲突"的那类。无修改授权的评估,收敛判据读作「一整轮下来零新增发现」——发现只记录不清零。

**管辖面是整个 skill,不止 SKILL.md**——SKILL.md 对某个资产的**描述**与该资产自己的说明尤其容易对不上。**判据**:枚举该 skill 管辖的全部文件——目录内的引用文档,**加上正文或引用文档里以路径引用的资产**(资产常放在多个 skill 共用的目录下,按目录枚举必然漏掉它们)——对本次未触碰的每一个也给出「需不需要跟着改」的结论;答不上来的文件,就是没审。

**凡可枚举的检查,先全量提取成表,再对着表逐项判**(指代、软化词、条文清单皆然)——通读着找必漏,而漏掉的那条不会自己现身。**表里每一项都要留下结论**,不得只报命中项:只报命中时,「漏看了」与「看过判合规」在产出上无从分辨,而前者恰恰是要防的。

**顺序是硬的。** 阶段一每次只有一条条文在视野内,**单看每条都正确、合起来才互相锁死的冲突在其中永远不会现身**——跑多少轮都一样,而"已经审过 N 轮"恰恰会盖住它;阶段二必须排在阶段一收敛之后,因为改措辞本身就会造出新的冲突。

### 阶段一 逐条审措辞,循环到收敛

对在审范围内的每条条文(不论落在 SKILL.md、引用文档还是资产说明里)逐一问:
- 是命令还是描述?描述 → 改写为命令或删除。
- 删去具体人、事、时、地后还成立吗?不成立 → 抽象未完成,继续提炼。
- 判据能当场执行吗?不能 → 补判据,或整条删除。规定往哪边取的,按 §1 的偏好规则试举反例。
- 句中的指代与自定义术语有锚点吗?判据见 §1 的锚点规则 → 失锚则补锚点或改写成直述,倒置则前移定义。
- 泛化或收紧措辞时,原有的限定词丢了吗?判据见 §1 的限定词规则。**审既有 skill 时本条读作**:条文有没有作出它的机制支撑不了的断言,用同一个反例测试。但**只对承载判据的条文生效**——举例与机制性理由里的陈述即便偏宽,若不改变读者该做的动作,记录即可、不动手;**只有当过宽会让读者少做该做的事时才必须改**。
- 引用了别的 skill、它的文件或全局指令,或拿别处的执行当本处的依据吗?按 §4 判 → 违反的按 §4 改(规则留下或移走),多余的删掉。

**这一轮只要动过手,就得重跑整轮**——改动是否带进新问题,不重跑一遍是不知道的。**改了某节的标题、引言或适用范围,该节全部条文都算被改动**,逐条重审。**收敛判据:一整轮下来零发现**,这一阶段才算完成。

### 阶段二 对读

**先归堆,不要两两穷举全文**:拿每条条文问「它在约束什么」,答案即受约束对象;把约束同一对象的条文归到一堆(不论同节异节)。堆通常只有两三条,而穷举会把工作量推到没人跑得完,跑不完的检查等于没有。

**归堆必须可核,不是抽查**:按开头定死的条文单位逐条编号列出,每条至少归入一个堆,末了报出「条文总数 / 堆数 / 各堆成员编号」。有条文一个堆都没进,就是还有对象没被取出来。

**节标题也入审**:把每个节标题与引言当条文取适用面,节内逐条与之做包含比对(嵌套逐层)——条文适用面不在节适用面之内即错位(违反 §3),上提或换节。

**归属也入审**:拿每条条文按 §3「归哪个 skill、写在哪个时点」各条判,不符的照该节改。

堆内逐对给出「相容」或「冲突」结论——**每一对都要留结论**,不只报冲突的。判定冲突的,两条同属一个 skill 时,要么改一方,要么补一条写明前提的条文使两者相容;分属不同 skill 时,按 §3「归哪个 skill、写在哪个时点」办。

**冲突的判据**:举得出一个具体情形,使两条**无法同时满足**、或该情形**落不进任何一支**,即为冲突;每种情形都有唯一归宿、只是措辞宽窄不同则为相容。一条给分类、另一条给归属时,把分类的每一项与归属的每一支列成两列对齐,任何一项找不到唯一归宿即为冲突。

**堆内有同一条规则写了两处的**,按 §3 开头一段判是否复述并照办。

本阶段的每次改动都退回阶段一过一轮,再重跑本阶段,直到两阶段都零发现。
