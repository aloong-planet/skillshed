# 已调研、暂缓收编的两个框架

本文是参考存档,不是规范条文。收录两个经调研核实、但因"其针对的失败模式尚未在本 skill 库的 baseline 评测中实际观测到"而暂缓收编的框架。**命中下方任一回溯触发条件时,回到这里,按对应框架修订 SKILL.md;收编前先跑 baseline 对照评测**(无 skill 条款 vs 有条款,各 ≥5 次重复),不给想象中的问题写文档。

## 回溯触发条件(先查这里)

| 踩到的坑 | 回溯的框架 |
|---|---|
| 某 skill 把多解任务写成唯一步骤,agent 在不匹配场景下只能违规或硬套 | 框架一(自由度过低) |
| 某 skill 对脆弱操作只给了"建议/参考",执行产生不该有的方差 | 框架一(自由度过高) |
| 想往 skill 里加"不要…不要…"清单去治**产出形状不对**的问题 | 框架二(禁令治形状会反噬) |
| 想把硬规则软化成"建议优先…"去治**知规而犯**的问题 | 框架二(软引导治不了纪律) |
| 给一条运转良好的规则追加 "除非…" 式 nuance 子句 | 框架二(nuance 重开谈判) |

## 框架一:Degrees of Freedom 三档

出处:Anthropic 官方《Skill authoring best practices》,"Set appropriate degrees of freedom" 节
(platform.claude.com/docs/en/agents-and-tools/agent-skills/best-practices)。

写指令前按任务的**脆弱性与可变性**选自由度:

| 档位 | 形式 | 适用条件 |
|---|---|---|
| 高自由度 | 文字启发式指引 | 多种做法都对;决策依赖上下文 |
| 中自由度 | 伪代码 / 带参数的模板 | 存在偏好模式,允许一定变化 |
| 低自由度 | 精确脚本,少参数或零参数,"不得改命令" | 操作脆弱易错;一致性是硬要求;必须按精确序列执行 |

类比:两侧悬崖的窄桥 → 上护栏给精确指令;无危险的开阔原野 → 给方向让 agent 自己找路。
与 SKILL.md §1 的关系:§1 管措辞清晰度,本框架管内容收多紧,两者正交——高自由度的启发式同样必须用命令式写。

## 框架二:Match the Form to the Failure

出处:社区 obra/superpowers 仓库,writing-skills skill 的同名章节(含其对照措辞实验)。

写指引前先给 baseline 失败分类;**治某类失败的文体用在另一类上会实测起反效果**:

| baseline 失败类型 | 对的形式 | 错的形式 |
|---|---|---|
| 知规而犯(压力下跳过规则) | 禁令 + 借口对照表 + 红旗清单 | 软引导("prefer…") |
| 服从了但产出形状不对 | 正向配方/契约:规定产出**是什么**、有哪些部分、什么顺序 | 禁令清单("don't restate") |
| 漏掉必需元素 | 结构化:在其必填的模板里加 REQUIRED 槽位 | 模板旁散文提醒 |
| 行为应随条件变化 | 以可观察谓词为键的条件句 | 无条件规则 + 豁免子句 |

其对照实验的三条结论(前提:存在与规则竞争的动机时):
1. 禁令治形状问题,坏产出多于配方组,甚至差于无指引对照——agent 会与 "don't X" 讨价还价,配方无谈判空间。
2. 给获胜配方加一句 "unless it matters" 式 nuance,效果从稳定退化为噪声;真例外写成独立条件句。
3. 豁免子句不守边界("不适用于代码块"仍会压制代码块);要豁免就重构规则使其够不着该部分。
