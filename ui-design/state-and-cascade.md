# 状态与层叠的机制细则

对一切用户可见元素的交互态与层叠样式生效,与 SKILL.md 正文同等强制。这些条文约束的是尚未写出的
新现场,单个项目的现场注释承载不了跨项目的「新建时」约束,故按 SKILL.md 开篇的分层落在本文件。

**同族的判据**(第 1、4 节的「同一色族」「同族」按此判):两块底色取自同一个主题变量(含其不同透明度)
的,即为同族;否则读两者的计算值——RGB 三通道最大值与最小值之差不超过 16(0–255 标度)的按近灰算,
两块都近灰即同族,只有一块近灰即不同族;都不是近灰的,换算成 HSL 后色相在色相环上相差不超过 15°
(取两个方向里较小的差)即为同族。近灰不比色相:近灰的色相随通道上一两点的差异大幅跳动,比不出结果。
同值必然同族。

## 1. 同族交互态必须可分

- 悬浮态与选中态用同一色族铺底时,两态必须可分:选中的底色比悬浮深一档(同族加深),或两态底色
  同值、选中项另带悬浮项没有的形态标记——描边、内嵌环、侧边指示条这类占可见几何的标记;只有文字色、
  图标色不同不算形态标记,它们仍是取值差,同底色下读者分辨不出哪一项是选中的。**判据**:选中一项后
  悬浮其相邻项,两项底色的计算值不同;底色相同时,选中项上存在悬浮项上没有的形态标记,以计算值或
  几何量断言(描边或内嵌阴影的宽度非零、指示条的 rect 非空),且该标记在悬浮项上不存在。
- 选中态必须在与悬浮态同时成立时胜出(源序在后、更高特异性,或按 SKILL.md 第 4 节的例外以内联
  覆盖,任选其一)。**判据**:悬浮选中项本身,其底色计算值仍是选中值;靠形态标记区分的,标记仍在。

## 2. 选中环不得越出自己的盒

- 可与相邻元素贴合的项,不得用无偏移的 `outline` 画选中环:outline 绘制在 border-box 外侧且不占
  布局空间,环会压在相邻元素的背景上。要环时用负值 `outline-offset`、inset `box-shadow`,或占布局
  的 `border`(并补偿尺寸)。**判据**:几何断言——环外缘不超出该项自己的 border-box 边缘;不得以
  目测替代。

## 3. 容器 chrome 规则不得渗入渲染内容

- 承载外来渲染内容(markdown、富文本)的容器,其 chrome 元素——容器自带的标题、路径行、关闭钮等
  非内容元素——的样式规则不得用裸后代选择器(如 `容器 h2`):它与内容层的单类选择器特异性打平、
  靠源序取胜,源序在后的一方会静默改掉渲染正文里的同名元素。一律用子代组合器(`容器 > h2`)或
  专用 class。**判据**:对渲染内容里出现的每类元素,chrome 规则的选择器均不命中(可用
  `matches()` 逐选择器断言)。

## 4. 相邻同色块必须可分

- 可能同时着同族底色的相邻块(相邻列表行的选中与悬浮、并排卡片)之间必须有不小于 1px 的间距,
  或一条与两块底色都可辨的分界线;零间距的两块圆角底相贴会读作一块。**判据**:两块同时着色时,
  两者的 border-box 不相接,或交界处存在分界元素。

## 5. 浮层必须逃出裁剪,并为测得的位置负责

本节的浮层指定位到某个锚点旁、可能越出所在容器的层:提示框、下拉、弹出菜单。

- 浮层必须同时满足两条:逃出祖先的 overflow 裁剪;位置从锚点的测量 rect 算出,并在该 rect 失效
  (锚点所在容器滚动、窗口 resize、锚点被过滤掉)后重新定位或关闭。满足其中一条不得当作另一条也已满足:
  逃出裁剪只让它可见,不让它指对位置。**判据**:浮层中心点的命中测试(`elementFromPoint`)返回浮层
  自身或其后代——被裁掉或错位的浮层报出的 rect 与正常的一样,存在性与包围盒都不构成证据;滚动锚点所在
  容器、resize 窗口后,浮层已关闭,或其 rect 与锚点的新 rect 仍保持设计的相对位置。
- 视口定位(`position: fixed`)本身即逃出祖先裁剪,不得为此再把浮层挂到列表之外;仍能裁到它的只有为它
  建立包含块的祖先。**判据**:从浮层向上到根,没有祖先的 `transform`、`filter`、`perspective` 取非
  `none` 值。
- 浮层自身内容的滚动不得触发重新定位或关闭:监听挂在 document 捕获阶段时,它同样听得到浮层内部的滚动,
  可滚动的浮层若因此关闭,折叠线以下的内容就再也够不到。**判据**:滚动浮层内部后,浮层仍在原位。
- resize 时,用户正在其中操作的浮层(菜单、下拉)必须重新定位,不得关闭;只被瞥一眼的浮层(悬停提示)
  可以关闭。**判据**:打开菜单或下拉后 resize 窗口,它仍打开,且与锚点保持设计的相对位置。
- resize 后固定时窗内到达的 scroll 事件必须归给 resize,不得当作用户滚动:浏览器把滚动容器的 scrollTop
  夹回新范围时会派发 scroll,事件层面与用户滚动无从区分,不归因就会关掉 resize 刚重新定位的浮层。时窗取值
  必须写在实现处;同时派发两类事件的测试,滚动用例必须落在该时窗之外,否则断言的是归因而不是关闭。
