# 界面改动硬性规范(跨项目)

改动任何用户可见界面时必须遵循。本文件只管代码注释管不住的事:需要停下来问用户的流程、跨文件才成立的约定、"不该顺手改什么"、以及改完之后凭什么算验收通过。具体写法的依据在项目代码现场(锚点文件的头部与章节注释、既有同类样式);新学到的写法规则一律先写进使用现场的注释,只有注释承载不了的才补进本文件——注释在必经之路上,skill 可以被绕过。

## 0. 先定位项目的锚点

动手前逐一定位下列锚点并读完其文件头/章节注释:

| 锚点 | 形态 |
|---|---|
| 图标模块 | 集中存放内联 SVG 图标组件的文件(如 icons.tsx) |
| 主题样式文件 | 定义颜色变量与交互态 class 的样式文件(如 theme.css) |
| i18n 字典 | 用户可见文案的唯一来源(如 dict.ts) |

定位手段:项目根的 AGENTS.md / CLAUDE.md 或 CONTEXT.md 有记载则从记载;否则按上述形态全库搜索。**判据:每个锚点要么"已找到并读完注释",要么"已确认该项目不存在此锚点",二者必居其一;否则不得改界面代码。**

**i18n 字典与主题样式文件这两行先看项目能力声明**(`capabilities.toml`,读写规则见全局指令的「项目能力声明」节):能力 `i18n` 未启用时,字典锚点连同本 skill 全部字典相关条文一律不适用;能力 `theming` 未启用时,主题样式文件锚点连同第 4、5 节与第 8 节中指向主题样式文件的条文一律不适用;两种情形都不得判为锚点缺失。启用时锚点位置取该项的 `source`,再照上述判据读完注释。

## 1. 图标选型不唯一时,必须先给用户预览让其选,不得自己拍板

**触发判据**:一个语义能找出两个及以上合理的图标候选,即触发本条。候选取自项目既定图标库;项目无既定约定时用 Lucide。找不出第二个合理候选时不触发,直接用。

- 预览用 Artifact 页(先按 `artifact-design` skill 校准,做成克制的功能性对比页)。
- 候选**用图标库真实 SVG 渲染**——照抄官方内部元素,不得用文字描述代替:选型看的是字形,描述传不出字形。
- 按该图标在界面里的**实际几何**摆放(容器宽度、行内边距、按钮盒尺寸、图标 size),并把相邻元素(角标、选中态、相邻按钮)一并放进去——图标在空白页上都好看,挤在真实行里才看得出干扰。
- 深浅色并排;成组图标必须并排看协调度。
- 每个候选给一句语义说明,标出推荐项。
- **用户选定前不得改图标模块与调用处**。代码可先接推荐项,但交付说明里必须写明"待确认,换候选只是改 path 的事"。
- 原型阶段已随原型确认过的选型,实现阶段直接沿用,不再二次征求。
- **用户已选定的选型不得再改**:换候选要重走本节的预览与确认,不因"实现时发现另一个更协调"就自行替换。

## 2. 改动面外的字符图标:必须报告并给出归宿,不得擅自替换,也不得沉默

改界面时发现本次改动面之外还有 emoji / Unicode 字符 / 单字符被当图标用(它们违反第 3 节),按三步处理:

- **不改**:替换它们各自需要一次第 1 节的选型确认,顺手改就是越界。
- **必须报告**,且首次提出就带齐三样:影响面(哪些文件、什么场景下用户看得到)、建议处理(现在做 / 另开任务 / 不做,给推荐并说明理由)、归宿(建票 / 写进项目约定文档 / 明确不做)。
- **只写在交付说明里不算报告**——对话会蒸发。必须明确说出"它没有持久落脚点,请定归宿"。

**判据**:交付时能回答"本次改动面外的字符图标有哪些、分别在哪、下一步归谁"。清点以**图标承载结构**为准——图标组件、工具/映射表、JSX 或模板里的图标位——逐一枚举;字符类别扫描(如全码点枚举)只作补充:纯 ASCII 字符(如单字母)也可能被当图标用,类别扫描抓不到它。手挑几个字符做 grep 不构成清点;做不到穷举就如实写"本次未穷举"。

## 3. 图标只用图标模块里的内联 SVG,禁用字符

**严禁 emoji / Unicode 字符 / 单字母当图标。** 机制性理由(为何必须内联、字符字形为何大小不齐)应写在图标模块的文件头注释里,动手前读它;该项目图标模块没有这段注释就补上。

- 已有图标:从图标模块 import 使用。
- 缺图标:把图标库官方该图标的**内部元素**照抄进图标模块,套用模块的统一包装组件;不引第三方图标库运行时依赖;不贴完整 `<svg>` 标签;不在 SVG 里写死颜色(跟随 currentColor)。

## 4. 交互态(`:hover` / `:active` / `:focus`):base 值必须落在主题样式文件

**凡是 class 的交互态规则要改的属性,该属性的 base 值必须写在主题样式文件的对应 class 中,不得留在组件内联 style 里。** 机制:内联样式优先级高于任何 class 选择器,交互态伪类也不例外;base 写内联会把同名属性的伪类规则整条压死,浏览器不报错、类型检查不拦截,表现只是"交互毫无反应"。

**判据**:元素的内联 style 属性名与其 class 交互态声明的属性名,两个集合不得有交集。例外:**故意**要盖过 hover 的选中态,base 就写内联,并在该 style 上注明用意。

## 5. 颜色走主题变量;先判定它在哪些维度上变化,再按维度分别声明

- 颜色一律用主题样式文件的变量,不硬编码色值(`#hex`、`rgba(...)`、具名颜色);语义已有的直接复用,不新造同义变量。
- 半透明色值按维度分别调 alpha:同一 alpha 压浅底可见、压深底可能不可见。

**新增变量前,先确定它随哪些主题维度变化。** 先列出本项目实际有哪些维度(明暗?多套配色?对比度?),
再问这一个问题——**它与所在表面是什么关系**:

| 它是什么 | 随哪些维度变 | 例 |
|---|---|---|
| **构成**表面或其上的文字 | 全部维度 | 页面底色、卡片、正文、描边、强调色 |
| 坐**在**表面上,要与之保持可辨 | 只随影响明暗的维度 | 阴影、状态底色、徽章底色 |
| 自带底色的不透明块,不依赖周围表面 | 都不变 | 危险按钮、提示块 |

**明暗维度上不得拿上表判要不要写**:上表判的是取值该不该不同,而明与暗一律都要写。

**明暗这一维度上,明与暗必须各有自己的声明,取值相同也照写**——取值相同不构成省掉一处的理由。
省掉的那处要靠继承补齐,而继承是隐式的:「刻意同值」与「漏写」在源码上完全一样,读者无从分辨,
且漏写处仍解析得出值(继承自另一态),不以缺值的形式暴露。两处都写,读者查"它在暗色下是什么"
时能在暗色块里直接读到答案,不必先回溯它有没有被覆盖过。

**明暗之外的维度(多套配色、对比度等),只在上表判为"变"的维度上写声明**,判为"不变"的不写。
这些维度的取值个数随项目增减,无条件全写会让不随其变化的变量凭空膨胀数倍。

### 判据:实测,不是计数

遍历全部主题状态(逐维度切换取值,读 `getComputedStyle`),确认

1. 每个状态都解析出**非空**值;
2. 取值的变化模式与上面判定的维度**一致**——该变的维度上确实不同,不该变的维度上确实相同。

模式对不上只有两种可能:某态漏了定义,或维度判错了。两种都值得停下。

**不要用"定义处数"当判据。** 处数是结果不是原因,它看不见最常见的那个失误:维度判错时每处都写了、
数目也齐,只是该不同的地方写成了相同、或反之,而这一类只有实测看得见。计数还有个附带毛病:
"变量块数"这个数字随维度增减而变,本身就会腐烂。

本目录的 [theme-vars.mjs](./theme-vars.mjs) 实现了这个判据。用法:

```
node ~/.agents/skills/ui-design/theme-vars.mjs <主题CSS> \
     --dim theme='html[data-theme="{v}"]':-,blue,amber --dark-media
```

**选择器与取值照项目实际写**:上例的属性名与取值只是示例,动手前从主题样式文件里读出真实的选择器形态;取值写 `-` 表示该取值不加选择器(默认值常直接写在 `:root` 里)。

它把变量按**实测出的变化维度**分组,并单独报出两类问题:

- **某态解析不出值** —— 变量压根没定义;
- **沿某维度「变了一半」** —— 该维度只有部分取值给出了不同的值。**这一档最要紧**:
  某个取值下漏了定义时,它会继承别处的值,于是"看起来还是在变",只是少变了一处;
  它不表现为缺值,所以只查"能不能解析出值"是看不见的。

两类都没有时退出 0,但那只说明**变得齐整**;"本来该不该变"仍要人对着分组判——
工具判不了设计意图。

需要 playwright(级联、继承与 media query 的求值只有浏览器算得准);优先用本机 Chrome,
其次用 playwright 自带的 chromium,都没有时明确报错并给指引——不退回一个算不准的实现,
因为"算错"和"算对"在输出上分辨不出来。

## 6. 图标按钮:固定盒模型 + 图标居中,复用既有样式

**图标按钮必须用固定尺寸盒子(显式 width/height)+ 图标居中(grid/flex 居中)定形,不得靠 `font-size` / `padding` / `lineHeight` 撑出尺寸**——字体度量与显式像素是两套盒高,同行对齐时基线不齐。

- 先找项目既有图标按钮样式,复用其几何,不新造一套。仅当项目没有既有图标按钮样式,或既有的按钮盒放不进目标位置时,才得另定盒尺寸,另定的仍按本节固定盒模型定形,并在交付说明里写明新的盒尺寸、图标 size 与不能复用的原因。**放不进的判据**:把既有盒放进目标位置后,所在容器(行、标签、输入框等)的宽或高随之变大,或盒越出容器的内容盒。
- SVG 传显式 size,略小于按钮盒,靠居中定位。
- 相邻按钮收紧间距用 margin 负值,不改全局 gap。

## 7. 验收:必须取得渲染结果,类型检查与测试全绿不算验收

**凡改动用户可见外观(位置、尺寸、层叠、颜色、图标),不得仅以类型检查与测试通过作为验收依据;必须取得改动后的渲染结果并核对。**

机制:类型检查看的是接线,单元测试看的是逻辑,端到端测试看的是可达性——三者都不读"它渲染在哪、盖住了谁"。而 CSS 的失效方式恰恰全在这一层,且都不报错:特异性打平后由书写顺序定胜负、祖先裁剪、层叠上下文、伪元素承载不了元素。

**按被验证的属性选取证形式:**

- **整窗截图**——验"看起来对不对"、"指令指对了没有"。裁剪会把参照物一并裁掉:文案说"点左下角"时,左下角那个控件必须出现在同一张图里,否则这张图证明不了指令是对的。
- **读计算值与几何量**——验"这条规则生效了没有"。取计算样式或元素 rect 断言具体数值;它能指出是哪条规则赢了,截图只能看出结果不对。

**判据:说得出改动后的界面是怎么看到的**——哪张图、哪个数值。答"测试全绿"即未验收。**取到的证据与预期不符时,先判是证据取错还是改动错**:改动没生效、量错了对象、产物是旧的,都会长出同一种"不符";未判明前不得改代码去凑那张图。

**渲染结果必须来自当次改动的产物。** 凡读构建产物的取证(端到端、截图、烟测),跑之前先确认产物是新的;测试运行器不触发构建步骤时量到的是上一次的产物,而那张图会长得像"改了但没生效",诱使去改一个本来正确的修复。

## 8. 通用

- **匹配现有风格**:对齐周边组件的写法/命名/间距,不得顺手重构没坏的样式(见「窄而完整」)。
- **改动必须落在锚点文件**:图标进图标模块,颜色变量与交互态进主题样式文件。
- **新增样式类名前,必须先全库检索该名的占用,已被占用则换名**。类名是全局命名空间:同名类的
  规则互相叠加,同特异性下后写的逐属性覆盖先写的,而这不报错、也不被类型检查/构建/lint 拦截——
  失效形态是另一个组件静默变形,且受害处往往不在本次改动面内。检索须同时覆盖样式文件与组件
  标记(类名经拼接写入的,用词根检索)。**判据**:对本次新引入的每个类名,报得出检索式与其
  零占用的结果;报不出即未查。
- **新增用户可见文案走 i18n 字典**(能力 `i18n` 未启用时本条不适用,见第 0 节),各语言成对补齐,不在组件里写死单语言文案;同义动作优先复用既有 key,**仅限复用无需改动其它文件时**——需要重命名或迁移既有 key 才能复用的,按改动面外发现处理(报告并要归宿),不得为复用扩大改动面。
- **用户可见文案不得把某个可枚举维度的成员当全集列出**(支持的数据源、平台、语言、渠道):成员一增,这句话在所有语言里同时成谎,而没有任何一处改动会碰到它。指代全体时用不随成员数变化的说法,点名单个成员不受限。
