# 多语言(i18n)硬性规范

本文件只写**做错了不会有人告诉你**的部分——那些编译能过、测试全绿、界面看着正常,却已经坏掉的地方。

**适用前提**:各节自带前提——**类型对齐**依赖静态类型系统(无类型系统的语言里,漏译只能靠门禁扫描兜,须另设一道比对各语言 key 集合的检查);**跨进程收口**只适用于前后端分进程的架构;其余各节与技术栈无关。用不上的节直接跳过,不要为了套用而扭曲设计。

## 0. 动手前必须先定的先决条件

缺任一即不得开始抽取文案:

- **项目能力声明**。`capabilities.toml` 里能力 `i18n` 写成启用,`source` 指字典目录(字段格式见 `/repo-scaffold` 的能力登记表,读写规则见全局指令的「项目能力声明」节)。它是别的 skill 判断"要不要查文案层"的唯一依据:漏写会让此后每一轮文档收口都跳过字典,而跳过是静默的。
- **语言集,以及是否承诺 RTL**。RTL 不是"多加一种语言",它要求整套布局镜像:物理属性(margin-left、text-align: left)全部换成逻辑属性,以及任何按像素计算的定位逻辑都要镜像。**决定不做 RTL 必须落进项目的决策文档**(有 ADR 就落 ADR)——否则每次加语言都要重新争论一次。
- **源语言是哪个**。它是文案的唯一真相,其余语言从它派生;新增文案先落源语言。
- **仓库工作语言与产品 UI 语言是两件事**。前者即 `capabilities.toml` 的 `working-language`,管辖范围以 `/repo-scaffold` 能力登记表的定义为准;后者管用户看见的字。两者可以不同,但必须各自明确,否则"这段非工作语言的文字要不要翻"每次都得重判一遍。**工作语言若也设了门禁,其豁免一律写成形状谓词**(什么形态的内容可以是另一种语言、为什么),不得写成允许的行数——行数记的是此刻的事实而非允许的理由,任何合法增改都会撞线,教出的唯一反射是把数字改大。

## 1. 枚举值不得使用自然语言词

**运行时值一律用语言无关标识符,显示名另置一张表。** 用自然语言当枚举值,等于把"翻译文案"和"改类型定义"绑成同一件事。

**动手前必须查清该值有没有被持久化**,这是**否定判断**,不能靠印象:落盘文件、缓存、数据库列、曾经写入过的历史值都要查。**查的是全历史的写入面,不是当前引用**——当前没人引用,不代表历史上没写进用户的磁盘。

用 `git log -S` 查历史时注意两点:**检索路径要排除该值的定义处**,否则命中的是"引入这个值"的提交本身,得到假阳性;以及它只覆盖**源码里出现过的字面量**,动态拼接的键、用户手工写进配置的值它查不到——这两类要另外用运行期落盘结构的字段全集去核。

**特别当心值被当作映射的键**。以字符串为键的结构(字典、map、`Record<string, T>`)里键只是字符串,**两端用的不是同一批键时程序照常运行、不抛错也不告警**,表现为该维度的数据静默变空(总数还对、图表还画得出来,只是分组没了)。判据:键的产生端与消费端是否都源自同一份定义;不是的话,补一条用产生端函数造键、经消费端读取的链路测试。

**运行时按值分支的校验同样漏在类型之外**:把枚举收紧成联合类型只管编译期,而 IPC 入参校验、白名单判断这类**手写枚举字符串**的地方类型看不见——枚举增员时它们静默拒掉新值。判据:枚举的成员集有没有一处正身可导出;手写比较的每一处都改为引用它。

## 2. 复数走平台内建规则,期望值必须实测

**不得自造复数规则表。** 各语言的分型差异大到无法凭直觉穷举,用平台内建的复数规则 API。

**测试的期望值必须先跑一遍实测打表,不得凭记忆写。** 凭记忆写时实现和期望会**一起错**,测试照样绿——这是本节唯一重要的判据。

实测反直觉的几处(前提:CLDR 规则,不同运行时版本可能微调,以实测为准):

| n | 俄语 | 法语 | 英语 |
|---|---|---|---|
| 0 | many | **one** | other |
| 1 | one | one | one |
| 2 | few | other | other |
| 5 | many | other | other |
| 21 | **one** | other | other |

俄语 0 归 many 而非 other、21 归 one 而非 many;法语 0 用单数而英语 0 用复数——**把法语 0 与英语 0 并列断言**,实现若把规则写死成某一种,必有一条会红;只测其中一条则两种实现都能通过。

调用方须给出该语言用得到的全部分型——**分型清单向复数规则 API 自己要**(它一般提供查询某语言实际使用哪几型的方法),不要靠猜。并让类型强制"兜底型"必填:缺省回落若写成"都没有就返回空串",界面会显示空白而没有任何东西报错。

**复数条目一律建模为按数量取词的函数,不得做成按分型分键的对象。** 各语言的分型集本就不同,而按分型分键会让分型集变成字典结构的一部分,被第 6 节的类型对齐**按源语言锁死**:源语言只有一型时,分型多的语言连补齐自己的分型都通不过编译,那些语言的复数于是永远是错的,且全程零报错。建模成函数则各语言在函数内部各用各的分型集,两节不冲突。

## 3. 系统语言是一个列表;界面语言与区域格式是两套设置

取用户语言的 API 通常返回**按优先级排序的列表**。平台上往往还有另一类看起来很像、实则返回**区域格式**(数字、日期、货币的呈现习惯)的 API,那与语言不是一回事,不能拿来选语言。

**判据**:选之前读该 API 的官方描述,看它讲的是"用户偏好的语言"还是"区域/格式";返回单值的多半是后者。这两类 API 的文档常常互相指路,指向谁就用谁。

**必须遍历整个列表取首个受支持者**,不是"首项不受支持就回退默认"。

**这条的测试必须用多元素输入**:两种实现对单元素列表的输出完全相同,只有 `[不支持, 支持A, 支持B]` 这样的输入能区分它们。用单元素测等于没测。

标签可能带地区或脚本子标签,按主子标签匹配;匹配不上继续看列表下一项,而不是立刻回退。

**反过来也不得拿界面语言当日期、数字、货币的格式依据。** 这是两个独立设置,用户完全可以把界面设成一种语言、却仍用另一地区的日期顺序与小数写法。取错了不报错,只是月日顺序、小数点、货币位置悄悄换成另一套——**开发者自己的语言与区域多半是配套的,于是本机测出来的正是对的**,所以开发期不会暴露。这也就给出了检出办法:拿一对**故意不配套**的语言与区域去测。

**要把「界面语言 A + 区域 B」合起来用时,必须实测确认它真的生效。** 平台常常静默退回该语言的默认区域——请求的标识被接受、不报错,回读到的却是另一个。判据:格式化器一般能回读"实际生效的标识",拿它与请求值比对,两者不同就是区域没应用上。(实测于**某一个** CLDR/ICU 运行时:请求「中文 + 德国区域」,回读到的是「中文」,数字仍按中文默认分隔符;该运行时上区域覆盖扩展也没生效。换个运行时或版本结论可能不同——正因如此才要回读,不要把这行当结论抄走。)

## 4. 偏好与生效值是两个概念,不得合并成一个字段

**「跟随系统」是一条持续生效的策略,不是选中当刻的快照。**

- **偏好**:用户选的,被持久化,取值含"跟随系统"这一项。
- **生效值**:界面此刻实际使用的,恒为具体某个语言,由偏好推导,**不持久化**。

把解析结果直接存进偏好会造成两个后果:用户改了系统语言而应用停在当初解析出的那个值;以及再也分不清"他当初选了跟随系统"与"他当初手选了这个语言"。

判据:写入"跟随系统"后读回,拿到的仍须是"跟随系统"。

**这个模型不止用于语言**:凡是「跟随系统」与「用户锁定」并存的偏好都同构(界面明暗是已经验证过的第二例)。遇到第二个时直接套用,不要重新发明。

## 5. 界面语言必须在首帧之前确定

**不得在界面挂载后异步取语言。** 换配色只是变色、不易察觉,换语言是整页文字全变,首帧跳变一次非常刺眼。

做法随架构而变,判据只有一条:**首次渲染发生时,生效语言已经是最终值**。前后端分进程时,随窗口/页面的创建参数同步送达,不等 IPC 往返;服务端渲染时,在返回的文档里就把语言定死;纯客户端渲染时,要么在挂载前同步读出(本地存储这类同步接口),要么把首屏渲染挡在语言就绪之后——**不许先用默认语言渲染一次再纠正**。

## 6. 漏译与漏抽由两道不同的机制拦,不得混为一谈

- **漏译**(某语言少了一条)→ 由**类型系统**拦:源语言的形状派生出其余语言必须满足的类型,少一条即编译失败。
- **漏抽**(源码里还有没进字典的文案)→ 由**扫描门禁**拦,挂进验证网关。

两者覆盖面不重叠,缺一不可。

**类型对齐的做法**:由源语言的形状派生映射类型,逐属性重写——函数保留原签名、嵌套对象递归、其余放宽为字符串。**函数分支必须排在对象分支之前**:函数在类型系统里同样满足"是对象",顺序颠倒会把带参文案当成嵌套字典递归下去。

**两道机制都必须证明能红**,各做一次变异:

- 类型对齐:写一个**故意少一条 key** 的语言模块,确认编译失败;再写一个**多一条 key** 的,确认同样失败。只验证"补齐后能过"是无效的——那不能区分"检查生效"与"根本没检查"。
- 扫描门禁:故意留一处未抽取的文案,确认它报错,再撤回。

门禁的白名单须显式且最小。逐条问"去掉它门禁会红吗"——不会红的条目是多余的,删掉。**每条白名单写明理由与退役条件**(什么情况下它就该被删),否则下一个读到它的人无从判断它还该不该在。

## 7. 「跟随系统」需要一个测试注入口

系统语言在测试环境里改不了。**不做注入口,与系统语言相关的验收就只能靠人反复改系统设置**,那等于没有自动化验证。照项目既有的环境覆盖惯例做一个即可。

## 8. 长文案复核要看两类,且真实失败形态往往是换行

**正文最长的语言与短标签最长的语言往往不是同一个**,原因是句子长度看词数、短标签的宽度看字宽,两者不同向。**不要凭语言直觉挑"最长的那个"去测,量一遍**:对最长正文段与最窄的定宽标签各取实测冠军,两个都要覆盖。只按正文长度推断,会漏掉标签被挤坏的那批。

**失败形态优先看换行,不是截断**。多数容器允许换行,于是长文案表现为行数变多、把布局顶开——而**溢出检查检测不到这种失败**(没有溢出,只是变高了)。断言要针对行数或高度,不能只断宽度或溢出量(在 DOM 里就是:只断 `scrollWidth` 抓不到)。

## 9. 跨进程不得传自然语言

多进程架构下,后端进程送到界面的**一切**用户可见文字都要收口,不只是错误。**"错误"这个心智模型会漏掉一整类**:藏在数据字段里的展示文案——探测失败的原因、占位与降级文本("读不到"、"未知")、截断标记、提示语、摘要模板。它们不是 throw 出来的,按"抛出点"去枚举必然漏掉。

做法:失败传错误码加参数,措辞由界面侧渲染;非失败的展示文案则把产出位置整个移到界面侧,后端只传结构化信号。

**枚举时用能穷举的手段,不是采样**;并警惕检索工具自身的假阴性——**任何返回意外空结果的检索,先确认它真的读了那个文件**,而不是直接当作"这里没有"。

## 10. 检索文案时必须扫全部语言,不能只看源语言

**译文会漂移出源语言没有的断言**——多一个数量词、多一处成员列举、多一句源语言没有的补充。这类漂移**不由本文件任何一道机制覆盖**:类型对齐只看 key 集合,漏抽门禁只看有没有进字典,两者都不读译文的语义。

**判据**:凡按内容检索文案(找该改的措辞、找违规写法),检索范围一律是全部语言的字典;**源语言干净不能证明其余语言干净**。写法上该避免什么由 `/ui-design` 第 8 节规定(那里是文案写作规则的正本),本节只管"检索时别漏掉译文"。
