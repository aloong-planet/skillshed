# Logic 原型

终端交互驾驶舱:用户亲手驱动状态模型。适用于业务逻辑/状态迁移/数据形状——纸面看着合理、推真实用例才露馅的问题。("长什么样"→ [UI.md](./UI.md))

## 产物结构

```
docs/prototypes/<功能模块>/<原型名>/
├── README.md      ← 问题段落 + 运行命令 + 指向图源的链接(不内嵌图副本)
├── model.mmd.js   ← mermaid 图源(单一正本,js 包装供画廊 script 加载)
├── logic.ts       ← 纯逻辑模块(验证后可整体提升进真代码)
└── tui.ts         ← 一次性驾驶壳
```

## 流程

1. **写下问题 + 画出模型**:①README 写一段话(在原型化什么模型、验证什么问题)+ 运行命令;②**mermaid 图写入 `model.mmd.js` 单一正本**(状态机用 `stateDiagram-v2`:状态/迁移/触发动作;reducer 的 action 即迁移标签;纯函数集用 flowchart 画数据变换),格式:`window.MERMAID_SOURCES['<module>/<id>'] = [{title, src}]`,README 只链接不复制。③预览走画廊(index.html 渲染该条目),同时在 manifest 条目上填 `mermaidSrc` 字段。
2. **选语言**:随宿主项目;不为原型引入新运行时/包管理器。
3. **逻辑隔离在可移植纯接口后**,按问题选形态(不按好接 TUI 选):纯 reducer `(state, action) => state` / 显式状态机(当"哪些动作现在合法"本身是问题时) / 纯函数集 / 带内部状态的类。零 I/O、零终端码、零 console.log 控制流;TUI 单向依赖它。这层分离是原型的遗产机制——验证过的模块可整体提升。
4. **最小 TUI**:每帧清屏整帧重绘(不追加滚动,永远一个稳定视图);帧 = 当前状态美观打印(一行一字段或格式化 JSON,ANSI 粗体字段名、暗色次要信息)+ 底部键位表 `[a] 加用户  [q] 退出`;读一键 → dispatch → 整帧重绘;全帧一屏放下。
5. **一条命令可跑**:接入 package.json scripts 等既有 task runner;没有就把命令写在 README 顶部。
6. **交给用户驾驶**:有价值的时刻是"等等,这不该可能"——那是想法里的 bug,正是原型的意义。要加动作就加,原型会进化;**模型演化了,同步改 `model.mmd.js`**——图与代码不一致即腐烂,过期的图比没有图危险。
7. **捕获**:答案记入 issue/commit;验证过的逻辑模块提升进真代码;mermaid 图(取自 model.mmd.js)内联进 spec 或作 ADR 来源;原型目录整体上一次性分支。

## 反模式

- 不加测试(需要测试的原型不是原型)
- 不接真实数据库(除非问题就是持久化)
- 不泛化
- 逻辑与 TUI 不许糊在一起(reducer 里出现终端码即不可移植)
- TUI 壳不许进产线(值得留的是它背后的逻辑模块)
