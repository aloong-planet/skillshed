# 视频教程

下文的 `pnpm` 命令都必须在视频项目根目录运行。

## 术语

- `<skill 目录>`：本文件所在目录。
- 模板：`<skill 目录>/template/`，新项目由它复制而来。
- 需求单：第 1 步表格列出的需求清单。
- `brief.md`：项目根目录里记录用户同意的需求单的文件。
- 默认要求：「稿子结构」「视频要求」「配音要求」「图片要求」「配色要求」「封面要求」六节的全部条文。
- 职责：框在系统里担任的角色，取值见「配色要求」的色系表。
- 色系：`src/theme.ts` 里 `HUES` 的一族颜色，按职责选用。
- 路径颜色：`src/theme.ts` 里 `TONES` 的 `teal`、`orange`、`violet`，用来标出要讲解的路径。
- 稿子：项目里的 `src/data/script.json`。
- 片段：稿子里 `segments` 的一项。
- 编号章节：稿子里 `chapters` 带 `no` 的章节，每个讲一种情况。
- `take`：一次连读生成的音频，包含一个或几个相邻的片段。
- 点亮：框或连线从调淡变成高亮，由片段的 `n`、`e` 指定。
- 走动：光点沿连线移动的动画，由片段的 `flows` 指定。
- `<slug>`：视频的英文短名，在需求单里定下，写进稿子的 `meta.slug`。

## 入口

必须先按下表判断从哪里开始。

| 情形 | 判据 | 做法 |
|---|---|---|
| 新视频 | 要从头做一个完整视频，没有指向已有项目 | 从第 1 步开始 |
| 修改已交付的视频，或接着做未完成的视频 | 项目根目录有 `brief.md` 和 `scripts/gate.mjs` | 读 `brief.md`；有新改动时，把要改的内容和受影响的部分发给用户，同意后写进 `brief.md`；再从受影响或未完成的那一步走到第 8 步 |
| 其他 | 不符合上面两行，如项目不是用本 skill 建的，或只要封面、只要配音 | 停下问用户：按第 1 步新建完整视频，还是不用本 skill |

## 两道确认门

1. **需求确认门**：用户明确同意需求单之前，只准读来源素材、查看目标目录是否为空和提问，不得建项目、写文件、生成音频或图片。判据：说得出用户同意的是哪句话。
2. **最终确认门**：用户明确同意第 6 步发出的预览之前，不得运行 `pnpm approve`、`pnpm render`，也不得用任何方式导出 mp4，低清预览同样不得导出。判据：说得出用户同意的是哪句话，那句话之后没有改过 `src/` 和 `public/`；每个 mp4 要么生成于用户同意之后，要么早于这一轮的改动。

## 默认要求的改动

1. 默认要求一律照办，只有需求单写明并经用户同意的改动才能优先于它。判据：每处与默认要求不同的地方都能在 `brief.md` 里找到。
2. 改动不得违反 `/diagram-design`。用户要改其中的规范时，必须停下说明冲突，由用户决定是否修改 `/diagram-design`。
3. 改动与 `pnpm check`、`pnpm stills`、`pnpm verify` 的检查冲突时，必须同时改项目里报错的那处检查，并写进 `brief.md`；动到 `src/`（`src/data/` 除外）或 `scripts/` 的文件时，必须同时更新 `template-sums.txt`。
4. 改动涉及版式或 `src/theme.ts` 的取值时，动手前必须先调用 `/prototype` 并经用户确认。

## 本机环境

`~/.venv` 不得删除；`~/.venv/mlx-tts` 未经用户同意不得升级或改动。

## 制作流程

必须按下列步骤的顺序执行，其余各节的条文在相关步骤必须遵守。`pnpm install`、`pnpm fonts`、`pnpm stills` 报网络错误时必须重新运行，连续三次失败必须停下告诉用户。

### 第 1 步：确认需求

1. 必须先把下表的需求单发给用户。用户没说到的项目，必须写上推荐答案一并请用户确认，不得省略该项，也不得当作已同意。
2. 需求单必须逐项写明下列内容：

| 项目 | 必须写明 |
|---|---|
| 来源素材 | 文章、文档或链接 |
| 观众和发布平台 | 给谁看，发到哪里 |
| 讲解结构 | 编号章节的数量、每章的名字和要点 |
| 图的内容 | 有哪些框，每个框属于哪种职责 |
| 封面文字 | 主标题、副标题、3:4 封面的横幅文字（写进「稿子结构」的 `meta.outro.heading`） |
| 英文短名和项目目录 | `<slug>`，以及新视频放在哪个目录；目录必须不存在或为空，默认 `~/playground/<slug>` |
| 与默认要求不同之处 | 要改默认要求的哪些条文；没有就写「无」 |

### 第 2 步：建项目

1. 必须运行 `<skill 目录>/new-project.sh <项目目录>`。它报音源缺失时必须停下问用户。
2. 必须把用户同意的需求单写进项目根目录的 `brief.md`；需求之后有变化必须同步改写。上下文被压缩后必须以 `brief.md` 为准，不得凭记忆。

### 第 3 步：写图和稿子

1. 动手画图前必须调用 `/diagram-design` 并遵循其全部规范，再按「图片要求」写 `src/data/diagram.ts`。
2. 必须按「稿子结构」写稿子。
3. 图和稿子里的每条事实都必须能在来源素材里找到出处，并把来源素材列进 `meta.outro.sources`。

### 第 4 步：生成配音和字幕

1. 必须依次运行 `pnpm narrate`、`pnpm fonts`。之后稿子或 `src/data/diagram.ts` 有任何改动，都必须重新运行这两条；没改动的 `take` 直接复用缓存。
2. `pnpm narrate` 报下列内容时，必须按表处理，再重新运行：

| 报的内容 | 处理 |
|---|---|
| `take … over 40s` | 在片段边界把这个 `take` 拆成两个；只有一个片段的，`tour`、`step` 先把片段拆开，`title`、`card`、`outro` 缩短文字 |
| `no quiet point after …` | 改写该片段结尾的措辞 |
| `subtitle may overflow` | 把那一行拆成两行 |
| `subtitle order broken` | 把报错的那行和上一行合成一行，超宽时缩短文字 |
| `nothing recognisable was heard` | 改写报错里的那段文字，再失败就停下问用户 |

3. 拆行或合行时必须同步改这个片段 `flows` 的 `cue`；`outro` 不得拆行或合行，必须改写文字。
4. 必须读 `captions/voice-check.txt`：列出的是转写和稿子读音不同的位置，转写自身也会听错，因此不得据此直接判定读错，必须留到第 6 步交给用户试听。

### 第 5 步：自查

1. 必须运行 `pnpm check` 和 `pnpm stills`，两条的退出码都是 0 才能进入第 6 步。
2. 必须亲自看 `pnpm stills` 生成的两张封面、`out/stills/` 下全部 `step` 的静帧和其他每种 `kind` 至少一张静帧，并对照图和稿子逐项判断 `pnpm stills` 判断不了的内容：每个框的职责和色系是否对应、点明框自身身份的词是否写成 `title` 或 `key`、同一事物在框、连线、图例里是否同色、同类连线是否同一种走法、镜头是否裁掉了还需要看到的框。发现问题必须回第 3 步修改。

### 第 6 步：最终确认

1. 必须在后台运行 `pnpm studio`，再把下列内容一次发给用户：Studio 的地址（可以连同声音、字幕一起看）、两张封面的路径、`out/stills/` 的路径、`captions/<slug>.zh.srt` 的路径、`captions/voice-check.txt` 里待试听的位置、第 5 步逐项判断的结论、没有核对到的条目及原因。
2. 用户提出修改时，必须回到受影响的那一步改完，再重新走到本步。
3. 用户明确同意后，必须运行 `pnpm approve`。

### 第 7 步：转成 mp4

1. 必须运行 `pnpm render`，它拒绝时不得绕过：报 `No final confirmation` 必须回第 6 步，报 `changed after the final confirmation` 必须回第 5 步，报 `run pnpm narrate` 必须回第 4 步。
2. 必须运行 `pnpm verify`，退出码是 0 才能进入第 8 步。修复时改到 `src/` 或 `public/` 的，必须回第 4 步。

### 第 8 步：交付

必须先停掉第 6 步启动的 `pnpm studio`，再把下列四个文件的绝对路径发给用户：`out/<slug>.mp4`、`captions/<slug>.zh.srt`、`out/cover-3x4.png`、`out/cover-4x3.png`。

## 稿子结构

1. 文件顶层的 `voice`（配音设置）和 `fps`（帧率）必须符合「配音要求」第 1 条和「视频要求」第 1 条，模板里已经写好。
2. `meta` 必须写明：`slug`、`title`、`subtitle`、`unit`（编号章节叫什么，如「事件」「场景」）、`outro.heading`、`outro.sources`；片头要加一行小字时写 `note`。片头和封面都取 `title`、`subtitle`，不得另写一份。
3. `chapters` 里的编号章节必须写 `no`、`tab`（章名）、`source` 和 `quote`（页眉显示「source：quote」，与 `meta.outro.sources` 无关）、`result`（该章结论），其中 `quote` 不是谁说的原话时必须加 `plain: true`；其他章节必须写 `label`，有 `tour` 的章节还必须写 `sub`。
4. `segments` 的每个片段必须写 `id`、`chapter`、`kind`，并按下表编排，顺序是一个 `title`、若干 `tour`、每个编号章节一组（一个 `card`、若干 `step`、一个 `wrap`）、一个 `outro`：

| `kind` | 画面 | 必填 |
|---|---|---|
| `title` | 片头 | `lines` |
| `tour` | 全图总览，逐步点亮 | `lines`、`cam: "full"`、`n`、`e` |
| `card` | 章节卡 | `lines` |
| `step` | 镜头跟随路径，带步骤序号 | `lines`、`n`、`e`、`at` |
| `wrap` | 回到全图，亮出该章结论，无旁白 | `hold` |
| `outro` | 小结：第一行读 `outro.heading`，之后每行读一个编号章节，行数不得增减 | `lines`、`tail` |

5. `n`、`e` 必须填这个片段点亮的框和连线的 `id`。一个 `step` 必须点亮至少一条连线，点亮的连线不得有两种路径颜色。判据：`pnpm stills` 会报错。
6. `at` 必须填步骤序号的坐标，放在点亮的连线旁边；点亮的连线里有带路径颜色的，必须放在它旁边。判据：`pnpm stills` 会报错。
7. `flows` 必须填这个片段走动的路径，每项写 `{p, cue}`：`p` 是连线的 `id` 或 `routes` 的键，`cue` 是从第几行字幕开始走（从 0 数），要晚一点时加 `delay`（秒）。
8. 镜头裁掉了还需要看到的框时，必须用 `focus` 列出要留在画面里的框或连线；同一章里要从头重新点亮时，必须加 `reset: true`。判据：第 5 步看 `step` 的静帧。
9. 有旁白的片段必须写 `take`：片头、总览、小结和每个编号章节各用自己的 `take`，一个 `take` 只能放相邻的片段，读完不得超过 40 秒。
10. `lines` 的每一项必须写 `say`，内容是一行字幕。读音不对时必须改 `say`，字幕要保留原文时必须同时写 `show`。

## 视频要求

1. 画面、音频规格必须是：1920×1080，30 帧，AAC 48 kHz，响度 -16 LUFS（误差 1 以内），真峰值不高于 -1.5 dB。判据：`pnpm verify`。
2. 有旁白的片段时长必须由 `pnpm narrate` 从真实音频推导：内容越复杂停留越久，不得手写固定时长；只有 `wrap` 的 `hold` 和 `outro` 的 `tail` 可以手写秒数，`tail` 是片尾让出处停留的时间，不得少于 2.5。
3. 句间停顿必须保持短：不得调大 `scripts/narrate.py` 的 `PAUSE_BASE`、`PAUSE_SCALE`。判据同本节第 6 条。
4. 画面上只准有一层字幕，就是烧录的那一层。`.srt` 不得放在 mp4 同一目录，同名字幕会被播放器自动加载，叠成两层。判据：`pnpm verify`。
5. 字幕文字必须来自稿子，转写结果只用于定时间。
6. 版式必须沿用模板。判据：`pnpm check` 比对 `src/`（`src/data/` 除外）和 `scripts/` 的文件与建项目时的模板。

## 配音要求

1. 模型必须用 `mlx-community/Qwen3-TTS-12Hz-1.7B-Base-8bit`，音源必须用 Tanya（`voices/ref-tanya-s45.wav`），随机性必须是 0。
2. 转写必须用 `whisper-large-v3-turbo-asr-fp16`。
3. 配音和转写必须在本地运行：不得把旁白发给在线服务，不得调用付费服务。`pnpm fonts` 只发送去重后的字符集，不含原文，不算发送旁白。判据：音频只由 `pnpm narrate` 生成。
4. 音源必须只留在本机：`voices/` 不得提交进 git，不得上传到任何服务，音频不得发布成 Artifact。

## 图片要求

1. 图的内容只写在 `src/data/diagram.ts`，框、连线、文字的坐标不得写进别的文件。判据同「视频要求」第 6 条。
2. 字段必须符合 `src/map/geometry.ts` 的 `Diagram` 类型。判据：`pnpm check`。
3. `view` 必须框住全部的框、连线和文字。判据：`pnpm stills`。
4. 框里点明这个框自身身份的词（模块名、类型名）必须写成 `title` 或带 `key: true` 的行。
5. 嵌在大框里的框必须加 `nested: true`，灰色背景分组必须用 `bands`，列标题必须用 `notes`，共用一条线的某个分支要走动时必须在 `routes` 里单列。
6. `legend` 必须列出图里用到的每种路径颜色和除 `gray` 外的每种色系，图例里路径那一列的文字不得压住色块。判据：`pnpm stills` 会报错。
7. 连线的 `d` 只能用大写的 M、L、H、V。判据：`pnpm stills` 遇到别的写法会报错。
8. 跟随路径时没走到的框和线必须保持模板的调淡效果。判据：看 `step` 的静帧。

## 配色要求

1. 视频和封面一律用日间外观，不得提供夜间外观。判据：`pnpm stills`、`pnpm verify` 的亮度检查，`pnpm check` 查夜间配色。
2. 色值只准写在 `src/theme.ts`，别处一律引用。判据：`pnpm check` 查十六进制、rgb、hsl 写法。
3. 框的色系必须按职责从下表选，表外的职责选一个没用过的色系，职责多于 7 种时必须停下问用户：

| 色系 | 职责 |
|---|---|
| `blue` | 外部系统 |
| `teal` | 程序层：由程序确定性处理，如入口、过滤、查表 |
| `amber` | 决策层：由模型判断和调度 |
| `green` | 执行层 |
| `violet` | 控制回路 |
| `pink` | 持久状态 |
| `gray` | 被丢弃或不参与的部分 |

4. 需要讲解的路径必须按类型用路径颜色标出：同一类路径用同一种颜色，不同章节走同一类路径时共用颜色；类型多于 3 种时只标最需要区分的 3 种，普通连线不标颜色。
5. 同一事物作为普通行（不是所在框自身的身份）或连线标签出现在多处时（如同一张工单），这些地方都必须写 `accent`，用 `ACCENTS` 的同一个颜色；`accent` 不得与 `key` 同用。
6. 标题、关键信息和序号的颜色由模板按色系和路径生成，不得另行指定。

## 封面要求

1. 封面必须做两张：3:4（1080×1440）和 4:3（1440×1080），不得另出别的比例；只有视频号后台提示的比例不同时，才以后台为准。
2. 主标题必须写清讲的是什么对象，只读主标题就能知道视频讲什么；副标题必须用一句话说明观众能看到什么。不得把稿子里的章节名或口号当主标题。
3. 主标题必须收进一行，字号不得大于模板默认值。放不下时必须调小 `meta.titleScale`，不得换行。判据：`pnpm stills` 报 `text leaves the frame` 即放不下。
4. 封面内容必须是：主标题、副标题、完整的图（不调淡、不带序号）、全部编号章节的名字和结论；3:4 那张还必须有 `outro.heading` 的横幅。
