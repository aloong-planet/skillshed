# 实现后复核(第 6 步)

本文适用于 `/implement` 第 6 步:全量验证网关通过后,把写成的测试交给独立子 agent 做实现后复核,处置它交回的发现,直到不再需要增量复核。入口:[SKILL.md](SKILL.md)「第 6 步」节。

必须调用 `/review-tests` 执行「实现后复核」并按其“记录归属”落盘本次各维度结论与发现。

本步必须交给一个不继承本次对话的独立子 agent 执行:由它自己按当前工具的 skill 机制完整载入 `/review-tests` 并执行——执行审查的是子 agent 本身,不属于让子 agent 代读 skill。交给它的只有全局指令文件、spec 与测试审查记录的路径,本次改动的 commit 范围,以及全量验证网关的日志路径(增量复核另加的材料见下文);交接中不得写入对测试有效性的判断或实现时的推理。复核要求的修改,由子 agent 记为发现,交回主 agent 处置;子 agent 只做[变异检验](../review-tests/mutation-testing.md)所需的临时改动,并按该文档还原。它执行期间,主 agent 不得改动代码、测试与测试读取的数据文件。复核结束必须以子 agent 交回的最终报告为准,不得以测试审查记录出现或被写入作为结束信号:记录在复核进行中就会被写入,据此判定结束,后续的修复、提交与交付就建立在未完成的复核上。当前工具无法派生子 agent 时,由主 agent 执行,并在测试审查记录里写明本次复核不是独立执行的。

**交出前自查**:复核交回的发现处置完毕后、跑下一段的定向验证之前,必须对本次修复的改动逐项自查;发现按 `/review-tests`「发现的范围」的三类归类,不属于三类的不得记为发现。下列各项一律要查,对应改动不存在的,写明该项不适用:

1. 修复改动的产品代码:与它实现的 spec 条文逐句并排核对,语义不一致即「缺陷」。
2. 修复新写或改动的每个断言:按 `/review-tests` 维度 3 的形态清单与检验法逐个核对,命中的按该维度处理。
3. 修复改动的每个函数:列出其中每个分支、每个退出路径(返回、抛出、超时)与每个被钳制的取值,连同本次修复新增的 spec 条文,逐条指出驱动它的测试或证据;指不出的,按「会漏掉的回归」的判据判定是否归入。
4. 修复新写的测试所用的数据:按 `/review-tests` 维度 1「fixture 不得与 spec 同源」与「会漏掉的回归」的判据核对。
5. 修复改动的共享测试辅助代码(fixture、测试替身、helper):按 [SKILL.md](SKILL.md) 第 4 步第 6 项的导入关系检索在全仓找出使用者,除去下一段定向验证将运行的测试文件,余下的(证据脚本、证据服务器等)逐个运行或核对;有使用者因此出错或产出不实的,按「发现的范围」归类。
6. 修复产出的证据:读数能否变化按 [false-greens.md](../review-code/false-greens.md) 判;输出、日志与命令全部留存,文件名与内容一致;不满足的即「不实的记录与证据」。
7. 修复涉及的记录(用例设计表、测试文件头的缺口注明、feature checklist、文档同步清单):与事实不一致的即「不实的记录与证据」,在同一次修复里改完。

自查结论必须写进记录:第 1 项写进代码审查记录(按 `/review-code` 的「记录归属」);第 2–5 项写进测试审查记录的设计审查一节,有用例设计表改动的随其增量一并写(按 `/review-tests` 设计审查的「增量」条);第 6、7 项写进施工记录。自查有发现的,修完重做自查,一整轮零发现后才进入下一段。

交出前自查零发现后,修复改了代码、配置或测试读取的数据的,必须按 [SKILL.md](SKILL.md) 第 4 步第 6 项「整体完成后」的要求跑 lint 与该修复涉及的测试(清单按该项的检索规则得出),并把结果写成日志,日志内容按 [full-verification-gate.md](full-verification-gate.md) 对日志的要求;全绿才可提交,退出码必须显式挡住提交与交接。

随后必须按修复改动的内容决定是否再复核:修复没有改测试的可执行内容、也没有改测试读取的数据的(只改了文档、施工记录、产品代码,或测试中不影响可执行内容的注释与文档字符串),不再复核。测试的可执行内容是否改变,按 [full-verification-gate.md](full-verification-gate.md) 沿用上次全量结果的 ①、② 两项判定,命令与输出记入施工记录;缺任一项或该语言没有可用的语法树解析器,按改了处理。改了的,必须把修复提交为 commit,再交给独立子 agent 做增量复核:交接材料是上文「交给它的只有」所列各项,加上修复的 commit 范围与该修复的定向验证日志路径;其中的全量验证网关日志沿用最近一次全量的日志,不得为增量复核重跑全量——全量按 [full-verification-gate.md](full-verification-gate.md) 在交付前重跑。复核范围按 `/review-tests`「实现后复核」的增量复核条款确定。增量复核交回的发现,同样按上一段(修复后的定向验证)与本段处理。

⚠️ **内联验证不能抵扣第 5/6 步**:实现期的变异检验、真实数据核验只触及 `/review-tests` 的第三个维度(假通过排查);实现后复核中写成的测试与用例设计表的一致性核对、资源加载次数的运行时核对,以及 `/review-code` 的分层扫查与 spec 逐条核销,都没有替代物。
