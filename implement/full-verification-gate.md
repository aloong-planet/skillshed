# 改动写成之后的运行

本文适用于 `/implement` 在改动写成之后为验证它而跑的命令:实现完成后、送审之前的审查前运行,修复之后的修复后运行,每条测试命令在一次交付里的那一次完整运行,以及哪些命令不再运行。写测试与代码的过程中跑的命令(如每个纵切完成后跑的类型检查与该纵切的单测)属于写的过程,不归本文;`/features-catalog` 全 feature 收口逐项查证时作为证据运行的测试、陈述核对为取证运行的命令,以及按 [post-implementation-check.md](post-implementation-check.md)「处置发现」节「先查证再修」一条为得到一条发现所述的错误结果而跑的命令,也不归本文。入口:[SKILL.md](SKILL.md)「轻档路径」节与「实现」节第 5 项、[post-implementation-check.md](post-implementation-check.md) 与 [delivery-and-feedback.md](delivery-and-feedback.md)。

## 命令的界定与通则

- **测试命令与惰性文件**:测试命令指运行测试用例或被测程序的命令(单元/集成测试、e2e/端到端、冒烟测试);其余命令——lint、类型检查、扫描仓库文件的检查,以及读取惰性文件(`docs/` 下的文件与所有 `.md` 文件)的命令——不是测试命令,拿不准一条命令属于哪类的按不是测试命令处理。项目把几条命令串成一条命令的(如依次调用各项的项目脚本),按其中的每条命令分别归类;要不跑其中的测试命令,必须拆开分别运行,其余命令照跑。测试命令运行的测试按 [SKILL.md](SKILL.md) 文首的禁止视为不读取惰性文件,无须逐个核查;已知其中有测试读取惰性文件的,运行它的命令不算测试命令。
- **可执行内容变没变**:必须用本 skill 目录内的 [change-scope.mjs](change-scope.mjs) 判定(它把工作区与基线提交逐文件比对,惰性文件判为 `inert`,去掉注释后语法树不变的 JS/TS 与 Python 文件判为 `same`,其余一律判为 `changed`,细则与它看不到的情形以其头部注释为准):直接在工作区运行 `node <skill-dir>/change-scope.mjs --base <基线>`(`<skill-dir>` 换成本 skill 实际所在的目录),不必先暂存未跟踪的文件。退出码 0 即相对基线可执行内容没有变,1 即变了;其他值即判定出错,必须排除错误后重新判定,排除不了的报告用户,排除之前按变了处理。
- **lint 与 e2e 按能力**:lint 与 e2e 按能力 `lint`、`e2e-suite` 判定,启用的照其 `enforced-by` 跑,未启用的按全局指令「项目能力声明」节写明跳过。
- **失败即停**:每条命令的退出码必须直接取得,不经管道。任一条命令失败的,不得交出审查、文档核对或交付,必须修到它通过;修复按「修复后运行」条再跑。
- **不写日志**:不得把运行的输出写进检出或施工记录目录作为记录;为读取过长的输出而重定向到临时目录的不在此列。交付说明必须写明本地跑过的每条命令、它运行时所在的 commit(在未提交的改动上运行的,写明是哪个 commit 加上未提交的改动)与结果;PR 上 CI 的运行不抄进交付说明,在 PR 上看。

## 跑哪些

下列各条要跑的测试命令,按「不跑哪些」一节判为不跑的不跑。

- **审查前运行**:实现完成后、送审之前,必须跑类型检查、lint 与本次改动涉及的测试:本次新写或改动的测试文件、按导入关系检索出的导入被改模块的测试文件(导入目标不是常量的调用,如动态导入,必须逐个列出并判断它是否导入了被改模块),以及按文件名检索出的读取被改配置或数据文件的测试文件。清单必须由检索得出,不得凭印象挑选;检索结果为空的,检索命令与空输出必须写进交付说明。改跑这些文件所属的整条测试命令,同样满足本条。
- **修复后运行**:修复写完后,必须对修复所改的部分按「审查前运行」条再跑一次,清单按该条的检索规则对修复的改动重新得出;送审之后又加的别的改动同样办。
- **每条测试命令完整运行一次**:一次交付里,每条测试命令都必须在交付的代码上完整运行一次。由 PR 触发的 CI 工作流承担它的,这一次在 PR 的 CI 里运行,本地不得为此再完整运行它;不承担的,或交付不经 PR 的,在交付之前本地完整运行。承担的判据:该工作流的某个运行步骤里有一行命令以它结尾、且它前面是行首或空白(如 `xvfb-run -a pnpm e2e` 算出现了 `pnpm e2e`,`pnpm test:site` 不算出现了 `pnpm test`);判定所读的工作流文件与命中的那一行必须写进交付说明。PR 头上的 CI 运行里,运行它的那个 job 被跳过或没有出现的,按下列两支判:该 job 的结论是跳过、且同一次运行里按改动路径路由的门禁 job(名为 `CI gate`,即 `/github-ops` 的 checks-gate.md「固定名称的 gate 与按改动范围路由」一节所定的那个)结论为成功的,即 CI 判定这次改动不涉及它,不得在本地运行它;其余的(没有这道门禁、门禁不成功,或该 job 没有出现),这次没有由 CI 承担,必须在 PR 头的 commit 上本地完整运行它。扫描仓库文件或读取文档的检查命令,按同一判据不由 CI 承担的,同样必须在交付之前本地运行一次。

## 不跑哪些

- **只跑「跑哪些」一节的三条**:这三条之外不得再跑:送审之前不得再跑「审查前运行」以外的运行,CI 承担的测试命令,除按「审查前运行」条末句改跑整条的那一次外,不得在本地完整运行,也不得因为把默认分支合并进了本分支而在本地运行任何命令——CI 会在新的头上运行,交付等它的结论。
- **不重跑**:一条命令在某段代码上通过后,对自那以来可执行内容没有变的代码不得再跑它。测试命令以它上次通过时所在的 commit 为基线按「可执行内容变没变」条判定,退出码为 0 的不重跑;不是测试命令的,只在工作区与它上次通过时所在的 commit 完全相同(`git diff <该 commit>` 无输出,且 `git status --porcelain` 不列出未跟踪的文件)时不重跑——它们读注释、格式与惰性文件,而判定脚本把只改了这些的文件判为 `same` 或 `inert`。一次运行开始前,`git status --porcelain --untracked-files=all` 列出了惰性文件以外的文件的,它测的不是某个 commit 本身,不得作为这里的基线。
- **可执行内容与分叉点相同**:必须先拉取远端,取 `git merge-base HEAD origin/<默认分支>` 得到的分叉点,以它为基线按「可执行内容变没变」条判定;退出码为 0 的,不得运行任何测试命令,包括 CI 工作流不承担的测试命令(如只在本地跑的冒烟测试),分叉点上有没有 CI 运行、运行的结论是什么都一样;不是测试命令的照跑。判定所用的命令、输出与退出码必须写进交付说明。
