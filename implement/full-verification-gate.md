# 全量验证网关

本文适用于 `/implement` 第 5 步之后、第 6 步之前的全量运行,每次全量里哪些测试命令可以跳过的判定,以及全量通过后又有改动时能否沿用上次结果的判定;实现后复核的复核者按本文核对交接的全量日志。入口:[SKILL.md](SKILL.md)「全量验证网关」节。

- 第 5 步完成(含其修复)后,必须跑全量(lint → 单元/集成 → e2e/端到端;lint 与 e2e 按能力 `lint`、`e2e-suite` 判定,启用的照其 `enforced-by` 跑,未启用的按全局指令「项目能力声明」节写明跳过),其中的测试命令能否跳过按本文「按改动范围跳过测试命令」条判定;按该条跳过的命令之外,其余命令**全绿才进第 6 步**;**退出码必须显式挡住后续动作**(进入第 6 步、提交、开 PR),不得仅记录失败而继续交付。
- 每次跑全量都必须把结果写成日志,日志必须写明:所测代码的版本——`git rev-parse HEAD` 的输出,以及 `git status --porcelain --untracked-files=all` 列出的每个文件的 `git hash-object` 输出(下称版本清单;已删除的文件写明删除);每条命令,取版本的命令连同其路径参数(如排除某目录的 pathspec)也算在内;不经管道直接取得的退出码;每条命令的完整输出。版本清单只得排除本次运行写出的文件,运行前已在工作区的文件即便位于日志所在目录也必须列出:被排除的既有文件若被这次运行读取,日志就证明不了它是哪个版本。第 6 步的复核者以这份日志作为全量运行的证据,按其中的版本逐文件对照交接的 commit 范围;缺任一项,日志就证明不了它对应哪份代码、是否真的全绿。
- 全量通过后又改了代码、配置或测试读取的数据文件的,交付前必须重跑全量;仅当同时满足下列两项时可沿用上次全量结果,两项的命令、完整输出与退出码必须记入施工记录:① 按本文「按改动范围跳过测试命令」条第 1 步取本分支上的全量作为基线(取不到的不得沿用),按该条第 2 步运行 [change-scope.mjs](change-scope.mjs),退出码为 0;② 改动后的代码上 lint 与 typecheck 都通过——lint 按能力 `lint` 判定,未启用的按全局指令「项目能力声明」节写明跳过;typecheck 即 [SKILL.md](SKILL.md) 第 4 步第 6 项所跑的那条。退出码为 0 说明改动只涉及惰性文件与只改了注释和格式的 JS/TS、Python 文件,可执行内容未变,上次全量的测试结果对改动后的代码仍然成立;脚本不区分注释是否被工具读取,lint 与 typecheck 读取的注释由 ② 核对。
- **按改动范围跳过测试命令**:全量里只有测试命令可以跳过——运行测试用例或被测程序的命令(单元/集成测试、e2e/端到端、冒烟测试);其余命令每次全量都必须照跑,包括 lint、类型检查、扫描仓库文件的检查与读取惰性文件(`docs/` 下的文件与所有 `.md` 文件)的命令,拿不准一条命令属于哪类的按照跑处理。全量由一条串起多条命令的命令运行的(如依次调用各项的项目脚本),按其中的每条命令分别归类;要跳过其中的测试命令,必须拆开分别运行。测试命令运行的测试按 [SKILL.md](SKILL.md) 文首的禁止视为不读取惰性文件,无须逐个核查;已知其中有测试读取惰性文件的,运行它的命令不算测试命令,必须照跑。判定用本 skill 目录内的 [change-scope.mjs](change-scope.mjs)(它把工作区与基线提交逐文件比对,惰性文件判为 `inert`,去掉注释后语法树不变的 JS/TS 与 Python 文件判为 `same`,其余一律判为 `changed`,细则与它看不到的情形以其头部注释为准;下文命令里的 `<skill-dir>` 换成本 skill 实际所在的目录)。进入第 6 步前的那次全量,本次改动相对默认分支改动了测试文件的,不得跳过任何命令——第 6 步要从这次全量的日志里取测试的运行结果。其余情形下能否跳过,必须按下列步骤判定,判定所用的每条命令、其完整输出与不经管道取得的退出码都必须写进该次全量的日志:
  1. **定基线**:必须取本分支上最近一次同时满足下列两项的全量,以其日志里 `git rev-parse HEAD` 的输出作为基线:版本清单里没有惰性文件以外的文件(否则它测的不是该提交本身);按本条跳过的命令之外,其余命令全部通过。这时全部测试命令都可以跳过。本分支还没有这样一次全量的,必须先拉取远端,取 `git merge-base HEAD origin/<默认分支>` 得到的分叉点作为基线,且必须先确认该提交上至少有一次默认分支的 CI 运行、全部运行的结论都是成功;这时可跳过的只限在该提交的 CI 工作流中出现过的测试命令——某个运行步骤里有一行命令以它结尾、且它前面是行首或空白(如 `xvfb-run -a pnpm e2e` 算出现了 `pnpm e2e`,`pnpm test:site` 不算出现了 `pnpm test`)。两种基线都取不到的,不得跳过任何命令。
  2. **判定改动**:必须直接在工作区运行 `node <skill-dir>/change-scope.mjs --base <基线>`,不必先暂存未跟踪的文件。
  3. **按退出码处置**:退出码 0,跳过第 1 步定下的可跳过的命令;退出码为其他值的,全部照跑。
