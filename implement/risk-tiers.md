# 档位

本文适用于界定与定下一次改动的档位:实施一次改动之前,以及切票时为每张票定档。收口票不定档位,不适用本文。入口:[SKILL.md](SKILL.md) 文首、`/to-tickets` 的 SKILL.md 第 3 步。

档位名(档位、轻档、标准档、核心档)写进票、交付说明等项目产物时,必须按 [本文的小表](../repo-scaffold/artifact-names/implement.risk-tiers.md) 书写。

## 三个档位

定档只按一条判据:这次改动出错的代价。不得按改动的行数定,也不得按改动从哪里来定——按票、按 spec、按用户的要求做的改动,以及需求先与用户对齐过的改动,都按同一判据定。必须先判核心档,不属核心档的再判轻档,两者都不属的即为标准档。

- **核心档**:改动出错可能丢失或损坏用户的数据、算出没人会发现的错误数字,或打开一个安全漏洞——改动的是这类数据怎样写入或删除、这类数字怎样计算,或一道边界放行什么。
- **轻档**:改动出错的代价低——错处在被改的东西第一次被使用时就会被看见,且撤回这次改动就能消除它。文案、样式、一个界面上的一处交互、症状可见的局部缺陷、文档、对测试或工具的小修属这一类。
- **标准档**:其余的改动。

核心档在标准档之上另加的,都写在执行它的地方:所触代码的代价条目计入覆盖清单(`/tdd`「覆盖来源」节「核心档改动另加所触代码的代价条目」一条),交给审查方的交接写明核心档([post-implementation-check.md](post-implementation-check.md)「交出」第 4 条),修复改动了产品代码的复审一次(该文件「复审」节);除此之外,核心档一律同标准档。

## 谁定档位与怎样说明

1. **切票时**:切票的一方必须为收口票以外的每张票按「三个档位」节评定档位。
2. **用户的声明**:用户可以为一次改动、一组票、一个项目或全部改动声明档位,在对话里作出,或写进指令文件(项目的 `AGENTS.md` 管该项目,用户的全局指令管全部项目)。声明优先于 agent 的评定与票里写的档位;几份声明都覆盖这次改动的,取范围最窄的那份。
3. **先后**:有用户的声明覆盖这次改动的,取声明的档位;没有的,按票实施且票里写了档位的,取票里写的;都没有的(包括按票实施而票里没写档位的),由实施这次改动的 agent 按「三个档位」节评定。取自票或自己评定的档位,再按第 5 项只升不降。
4. **开工前说出来**:开工之前,必须在回复里写明档位与理由,理由按这次改动出错的代价说;档位取自声明或票的,同时写明取自哪里。
5. **只升不降**:没有声明覆盖时,agent 可以升档,不得降档。开工前按「三个档位」节评定得比票里写的高的,按评定的档位实施;实施中定档的理由不再成立的——改动触及了「三个档位」节核心档所述的东西,或出错不再代价低——必须按更高的档位继续,并当即告诉用户;更高档位要求而尚未做的各项,必须在交付之前做完。不得取低于开工时评定的、或票里写的档位。
6. **声明之下**:有声明覆盖的,全程按声明的档位实施,不升也不降;agent 按「三个档位」节会评定得更高的,必须说出它会评定的档位——开工前就看得出的在开工前说,实施中才看出的当即说,声明的档位照样适用。
7. **写进交付说明**:交付说明必须写明这次改动的档位,以及它取自哪里——agent 的评定、票,或用户的声明。
