# 交付与验收反馈回写

本文适用于 `/implement` 的两个时点:全量验证网关的全量全绿后、开 PR 或以其他方式交付之前(「交付」节);收到用户对已交付工作的验收反馈时(「验收反馈回写」节)。入口:[SKILL.md](SKILL.md) 的同名两节。

## 交付

**开 PR 之前先验凭据**,缺任一不得开 PR:

1. 必须按两类审查 skill 的“记录归属”核对本次审查记录，读取内容确认版本、范围、发现及处置，不得只检查文件存在；按票交付必须据此核销票内对应流程验收。第 8 步跑过的，`final-regression.md` 同为凭据，判据以 `/features-catalog` 的落盘条款为准。按 [SKILL.md](SKILL.md)「小改动路径」节执行的，本项只核对 `/review-code` 的记录。按「收口票路径」节执行的,本项改为核对 [claim-check.md](claim-check.md) 的陈述核对记录与 `final-regression.md`;该节第 3 项判为有可执行改动的,再核对这些改动的两类审查记录。
2. 本次若改变**用户可见行为**,已调 `/features-catalog` 走完第 8 步(功能目录就地更新 + 本次范围的交叉回归),其产出与代码进**同一个 PR**。判据是两问——本次让 `docs/features/` 里**哪句话变成了谎**、又**缺了哪句话**;两问皆答「无」方可判为不改变可见行为而跳过,该判定须写进交付说明,不得默认跳过。**收口票不适用两问跳过**——两问答的是本票改动的后果,而收口票的职责恰是找出各票拼起来才出现的不一致,答案在收口跑完之前不存在。收口票一律走完第 8 步,**含 `/features-catalog` 的全 feature 收口**,同为开 PR 的前置条件。按 [SKILL.md](SKILL.md)「小改动路径」节执行的,本项由该节第 6 项代替。

第 2 条**不得延后到后续 PR**:功能目录描述的是默认分支上的产品,代码先合、文档后补会在两次合并之间留下目录说谎的窗口,而该窗口内没有任何检查会发现它。**编排范围止于第 7 步不构成豁免**——第 8 步不由本 skill 编排,但它是开 PR 的前置条件。

按票交付时，必须先执行 [文档同步与记录维护](document-sync.md) 的“核销前的范围复核”，再按 [Ticket 产物与文档同步清单](../to-tickets/ticket-artifacts.md) 的“文档同步清单结构与状态”重判各项状态；存在待处理项时不得交付。必须更新票内文档同步验收项，并按 [SKILL.md](SKILL.md)「验收时点与阶段门禁」处理后置验收；无用户可见行为变化而跳过第 8 步时，仍必须执行此项检查。

必须按 `/github-ops` 推送分支、开 PR 与合并;全套 e2e 交给 PR 的 CI 的,开 PR 后先按下一段取得 CI 的结论。

全量把全套 e2e 交给 PR 的 CI 的(判定见 [full-verification-gate.md](full-verification-gate.md)「全套 e2e 交给 PR 的 CI」条),开 PR 后必须按 `/github-ops` 等到 PR 当前提交上的全部 CI 运行结束。运行能力 `e2e-suite` 的 `enforced-by` 命令的那个 job,在这些运行里被跳过或没有出现的,全套 e2e 没有由 CI 承担:必须在 PR 当前提交上本地运行全套 e2e,结果按 [full-verification-gate.md](full-verification-gate.md) 对日志的要求写成日志;不全绿的,与下文 CI 运行不成功同样处理。全部结论为成功,才可报告交付完成,并把各运行的链接与结论写进交付说明;任一运行不成功的,按全量失败处理:修复后按 [full-verification-gate.md](full-verification-gate.md) 对「全量通过后又改了代码」的规定重跑或沿用全量,推送后再等,结论全部为成功之前不得报告交付完成。

## 验收反馈回写

- 收到用户反馈时，必须先定位已交付的票或 spec、版本与验收范围；只能确认部分范围时必须只记录该部分，无法定位时必须澄清，不得猜测票号或扩大验收结论。
- 用户确认通过后，必须在同轮按 [文档同步与记录维护](document-sync.md) 处理该事件触发的同步项，记录用户确认的时间、范围和可复查消息定位或原文摘录，并更新实际存在的 ticket、共享 checklist 与关联现行状态；失败反馈必须记录实际结果并重开受影响项。回写尚有阻断时必须区分“用户已确认”与“流程回写未完成”，不得宣称本票已全部收口。
- 必须将用户验收与合并授权分开判断；仅收到“测试通过”或“已验收”不得执行合并。获得合并授权并完成合并后，必须按 [文档同步与记录维护](document-sync.md) 处理合并事件触发的同步项。
