# 假绿:验证在该红的时候没红

**核心判据(对每一条验证都问一遍):它在什么情况下会红?**
答不出来的,就是嫌疑假绿——它证明的不是"东西是对的",而是"这条验证所用的断言恒真"。

假绿比没有验证更危险:没有验证时人会保持警惕,假绿会把警惕关掉,并让错误结论带着"实测过"的权威传下去。

**凡断言「X 不发生」,先故意让 X 发生一次**,看哪个可观测量真的动了,断言建在那个量上——失效形态靠想当然,断言就建在想当然上。

**凡结论建立在某个工具的输出上,先确认该工具真的作用到了目标对象,再解读输出。** 工具作用不到目标时,它的输出与"目标不成立"完全一致:空结果、正常退出码、无警告。这条原则有两支应用,各自的可枚举成因见对应形态——变异是否到达被测路径见形态四,检索/扫描是否读到被检对象见形态九。

## 适用范围

单元测试有专门的假通过清单([review-tests](../review-tests/SKILL.md) 维度 3 与 [tdd/tests.md](../tdd/tests.md)),本文不重复。
本文把同一条判据推到**另外三种常被忽略的语境**——这三种语境里的检查同样是验证,却很少被当作"需要设计的断言":

| 语境 | 典型载体 |
|---|---|
| 界面 / 浏览器行为 | 经调试端口或自动化工具读渲染状态并断言 |
| 关卡 | CI 门禁、分支保护、运行期断言、告警规则 |
| 命令行验收 | 用 CLI 检查产物、部署结果、外部服务状态 |

下列形态按这三种语境写,但其中多条(尤其一、五)对单元测试同样成立。

## 形态清单

### 一、断言"存在"冒充"生效"

`!!element`、`属性有值`、`文件存在`、`进程在跑`——这类断言几乎永远为真。
元素可以在 DOM 里却被祖先裁剪、被遮挡、定位到视口之外;进程可以在跑却没在服务。

**改法:断言可观测的效果或几何量**,而不是存在性。界面上就是元素与其容器的 rect 关系;服务上就是"发一个真请求看响应"。
再配一个**不变量**做交叉:内容变化时该量应当不变(如浮层"距容器底 30px"在内容长高后仍是 30px),这比单点快照更能证明行为。

### 二、用合成事件 / 手动触发替代真实路径(最危险的一种)

环境让验证跑不通时,绕过去让它变绿的诱惑极大:手动派发一个事件、直接调内部函数、跳过前置步骤。
**绕过去等于这条路径从未被验证**,而报告上写的是"已验证"。

典型:窗口被遮挡时浏览器会节流合成器,依赖合成器派发的事件(滚动等)不会触发,而 DOM 属性照常更新——于是"改了属性但状态没更新"看起来像业务 bug,手动派发事件就"修好了"。

**规矩:先修环境,不修断言。** 环境实在不可得时按下方「处理方式」办,不许用合成路径冒充。

### 三、选了分辨不出目标属性的命令

命令返回成功 ≠ 关心的那个属性成立。同一个对象,不同命令查的是不同的东西,而它们的成功输出长得一样。

判据:**这条命令在目标属性不成立时,会不会仍然成功?** 会,就换命令。
特别注意**联网回退**:很多校验类命令在本地信息缺失时会静默转为在线查询并成功,于是"离线可用"这个属性根本没被验到。

### 四、新建的关卡从没红过

新加的门禁、断言、告警,首跑必绿——首跑的绿没有证据。**一道从未失败过的关卡与没有关卡,在证据上等价。**

**规矩:新建或改动关卡后做一次变异验证。** 造一个明确的反例,预先写下"预期红在哪一步";**用独立于被测断言的证据确认变异到达了**(打印被测对象的实际内容、grep 构建产物、在渲染点打日志),再核对实际失败位置与错误信息是否一致——对不上说明关卡的实际行为与预期不符,要查清楚;拿不到独立证据,不得声称"变异验证过"。验完撤销变异。
多步关卡要**分别打不同的步骤**,证明每一步都在独立判定,而不是"整体挂了"。

**变异后没红,有两种原因,表现完全相同而处置相反**:验证恒真(要重写验证),或变异根本没到达被测路径(要修变异)。常见的没到达:同名符号在另一个作用域——"只替换一处"静默改错对象;构建产物陈旧——改了源码,跑的是上次的产物;模块缓存与加载顺序把变异前的版本先钉进了内存。

**变异后仍红,同样有两种原因**:变异生效了(该红,继续),或还原不完整、红的是别的东西(要修还原)。**判据:报错的文件与行号必须落在变异位置**;落不上就先查还原。注意在未提交的工作区里,把文件恢复到版本库的命令(`git checkout <文件>` 一类)丢弃的是该文件的**全部**改动,不只是变异那几行——正式修改一并没了,而它造成的红看上去正像"变异没清干净"。

### 五、读得太早或太晚

异步与过渡会让"当场读回"拿到旧值:CSS transition 期间读计算值得到的是插值起点;写操作返回后立刻读可能读到副本;事件派发是异步的。

**改法:等到状态稳定再读**(超过过渡时长、轮询到终态),或直接断言终态而非中间值。连续切换多个状态各读一次却得到同一个值,看起来像"切换没生效",往往就是这个原因。

**轮询的表达式必须就是被断言的表达式。** 轮询一个上游信号、随后读下游产物,两者之间隔着一次传播(状态更新、重渲染、样式重算),上游先到而下游未到的那段窗口里读到的是旧值。这个窗口的宽度与读取往返时间无关:窄于往返时它极少命中,一旦命中就被归为偶发不稳,而重跑总是绿的。**判据:把轮询的表达式与断言的表达式并排写出**,不是同一个就把轮询改成断言量本身。

### 六、验证命令自身出错,输出被当成数据

这一类最隐蔽:结论建立在一条**本身就跑错了**的命令上,而它的输出长得像事实。

- **管道后读 `$?`**:拿到的是管道最后一个命令的退出码,不是被检查的那个命令的。真实后果:上游命令被拒,脚本却打印"退出码=0"。
- **报错被 `tail` / `head` / `>/dev/null` 吞掉**:不熟的 CLI 传了不支持的 flag,整条命令失败,而管道只留下无关的尾部输出,看起来像成功。
- **中间产物为空导致的空集合结论**:集合运算的一侧因 glob 未加引号、正则没匹配上而为空,于是得出"全部都是孤儿/全部缺失"这类惊人结论。
- **shell 展开的意外**:含 `:` 的变量展开在 zsh 会被当历史修饰符;`--include=*.ext` 这类未加引号的参数会被 shell 先展开掉。

**规矩:凡结论要写进报告的检查,先确认命令本身跑通了**——不熟的 flag 先确认存在,不吞 stderr,不在管道后读 `$?`,含通配符或 `:` 的参数一律加引号,集合类结论先验中间产物非空。

### 七、豁免清单让门禁在该红的时候不红

与形态四相邻但不同:那条是关卡从没验证过能红,这条是关卡能红,**但豁免让它不看**。一条过宽的豁免与把被豁免的代码移出扫描范围在证据上等价,且伪装更好——门禁每天都绿着。

**豁免写成谓词(允许什么形态),不写成快照(允许多少、允许哪几条)。** 谓词是规则:「中文只能被*引用*、不能被*书写*」。快照是指纹——一个行数、一张条目清单、一份 baseline;它记录"今天恰好是什么",不是"为什么可以"。

指纹式豁免有两个失效方式,都不需要谁偷懒:**对正常增长开火**(被豁免的东西只要会长,每次合法改动都要动这条豁免,于是训练出"把数字改大 / 把新项加进去"的反射——而那正是门禁要防的橡皮图章;一道对每次合法改动都响的闸与没有闸等价),以及**对替换失明**(删一条合法的、加一条非法的,总数不变)。

**怎么写:问"为什么这里可以",把答案写成可判定条件。写不出来是诊断信号**——说明豁免的边界还没想清楚,该退回去想,而不是拿数字或清单盖住。

**怎么磨对:两个方向都要变异。** ① 违反规则的写法要红,且报错点明违反哪条;② **规则内的正常增长要保持绿**——只验①会磨出一个什么都拦的谓词。

确实无形态可分的(如"这个文件本身就是该语言的本地化"),才允许写一条放行全部的规则,但匹配范围要窄到不能悄悄扩大(精确文件名,不是 glob),并在代码里写明"这条永远不会红、安全来自匹配范围而非判定"——否则后人会当它有牙,照样再加几条。

### 八、几何/布局断言自己也会恒真

形态一的改法说"断言可观测的效果或几何量"——但几何量有自己的一套恒真方式,断言长得像一次真实测量,恒真得更隐蔽:

- **宽度自适应的元素上 `scrollWidth > clientWidth` 恒为 false**——尺寸随内容走,两者永远相等。
- **祖先有 `overflow: hidden` 时,文档级溢出检查永不触发**——内容被静默裁掉,没有滚动条,也没有任何溢出上报。
- **`white-space: normal` 的元素,可断行的内容不横向溢出,而是换行变高**——失效形态在另一个维度,横向指标一个像素都不动(无软换行机会的长词元不在此列,仍横向溢出)。
- **flex 默认 `align-items: stretch` 让「比兄弟高」类判据自我抵消**——一个子项换行会把所有兄弟拉到同一高度;数行盒(`Range.getClientRects().length`)不受拉伸影响。

上面四条全是没先让 X 发生一次就下断言的产物。

### 九、工具跑对了,但被检对象没进入它的检查范围

与形态六相邻但不同:那条是命令**跑错了**,这条是命令**跑对了**——退出码正常、无警告、输出格式正常——只是它没读被检对象。于是空结果有两种来源:目标不存在,和目标没被看;两者的输出逐字节相同。

危害集中在**否定结论**上:"没有别的调用点"、"没人引用它"、"这个形态不存在"。肯定结论错了会在下一步撞墙,否定结论错了没有下一步——没人复查一个"查过了,没有"。

**规矩:凡要写进结论的检索或扫描,先按下表核对被检对象确实在范围内。**

| 静默排除的机制 | 核对方式 |
|---|---|
| 被判为二进制(含控制字节、非 UTF-8) | 先用文件类型命令判一次;检索器按文本读的开关(`grep -a`、`rg --text`)重跑对比 |
| ignore 规则与包装器塞进去的默认 flag | 打印检索器的**实际命令行**——跳过二进制、跳过 ignore 列表的 flag 常由包装脚本或别名默认加上,调用者看不到 |
| 路径 / glob 未展开或展开成空 | 先单独列出展开后的文件清单,断言非空 |
| 权限、沙箱、符号链接未跟随 | 直接读一次目标文件确认可读 |
| 编码与规范化差异 | 按码点匹配,不按字面量 |
| 受限运行环境拦掉了被检行为(内容安全策略、只读挂载) | 断言被检对象自身的可观测状态,不断言它的副作用 |

**判据:说得出这次检索在被检对象上读了多少字节或多少条,才算它进过范围。** 说不出就是没核对。

**被检范围本身也会漏掉一整类载体**:按目录圈定范围时,以代码形态存放却在陈述事实的东西(界面文案表、包元数据、生成脚本里的常量)不在该目录下,于是从不进入任何一次检索——而它们与文档一样会腐烂。判据:这次要核的事实,除了文档,还有没有别处也在陈述它?

**枚举手段本身也会被同一机制排除**:用一个工具去找"该工具的盲区"是循环论证。按字符类别、按文件扩展名、按已知清单去枚举,漏掉的那批恰恰不在清单里——换成逐字节、逐条目的全量遍历。

## 处理方式

识别出的假绿按诚实原则处理:如实说明它没验到什么,不把假绿当真,不改断言去凑绿。
环境或工具确实做不到的,标注**缺口 + 补测条件**——诚实的缺口好过造假的绿。
