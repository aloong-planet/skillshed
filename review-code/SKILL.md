# Review 代码(第 5 步)

重读本次全部改动,目标是**找真 bug**,不是走形式确认。

## 四层法(自底向上扫;下层有发现,上层必须重扫)

1. **前提层**:这次改动依赖的事实还成立吗——API 的真实行为、时序假设、配置/环境、"我以为的现状"。前提错,上面全错。
2. **可运行层**:race / 资源泄漏 / 状态错乱路径逐条走。涉及状态/effect 的,把"该状态能从哪些路径进入/退出"列全,逐条对照实现(对照 spec 失败模式节,但不局限于它——实现暴露的新路径也要走)。
3. **安全层**:输入边界、路径穿越、注入、权限、敏感信息落盘/日志。
4. **一致性层**:反查"**本次改动破坏了哪些原有不变量或路径**"——回归高发区,重构时尤其。与既有约定(错误处理风格、命名、协议语义)冲突处,要么服从,要么写明为什么是有意的不一致。

## 产出(三件事,不是报告完事)

- **抓到的 bug**:修掉,并**补成测试**——先让新测试对着 bug 红一次(验证测试有效),再修绿。
- **攒下的重构在此做**:实现循环里踢出来的重构(红绿循环只做够过的实现),此时做,安全网就是循环攒下的测试。
- **缺 seam 补注入**:实现/测试过程中暴露的"测不动"(被迫 cast),在此补构造注入(规则见 /tdd 的设计信号条)。
